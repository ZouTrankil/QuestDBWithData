# 融资融券标的名单的正式有界补数

`margin_secs` 已支持精确同名正式目标。正式用作业 v2，只按明确日期窗口补数；默认仍为隔离目标和原作业 v1。本轮没有正式写入或启用日批。

```sh
# 只读检查一天的完整来源和旧范围，不创建运行账本。
APP_SYNC_MARGIN_SECS_WRITE_TABLE=margin_secs \
./gradlew run --args='check-margin-secs-source --date 2026-09-18 --logical-date 2026-10-21'

# 只生成计划，不写数据。
APP_SYNC_MARGIN_SECS_WRITE_TABLE=margin_secs \
./gradlew run --args='plan-margin-secs-job --mode BACKFILL --from 2026-09-18 --to 2026-09-18 --logical-date 2026-10-21'
```

日期换成实际要查的已完成来源日。执行命令是 `run-margin-secs-job`，参数与计划相同；恢复只传 `--resume-from 原运行编号`。正式唯一 writer、原账本和未决运行须先核清，不能同时启动第二个生产写入方。

## 正式 v2 为什么按窗口冻结

原表已有1618079行，原 v1 的百万行全表快照预算挡住了正式补数。没有扩大预算或让 v1 改解释旧参数，而是新增作业 v2：

- 数据版本仍是1，YEAR/WAL/DEDUP 及完整键 `(trade_date,ts_code)` 不变，`trade_date` 继续是业务日期的 UTC 零点载体。
- `baselineScope=DATE_WINDOW` 明确说明 `targetRowsBefore`、`targetFingerprint` 和原范围上下界只属于本次日期窗。范围外历史不被认证，也不被此次补数覆盖。
- 明确起止日，最多31个自然日。冻结窗口内全部 SSE 日历及开市日，冻结旧范围全部键值和物理代；正式读取还核对前后稳定 WAL 版本。
- 正式只允许 `BACKFILL`，不从旧行或最大日期推导历史增量覆盖，正式 v2 不进入自动日批。
- 原隔离 v1 的定义、全表基线、请求指纹和恢复方式保持。正式目标不接收 v1 请求，隔离目标也不接受正式 v2 请求。隔离 DDL 和原隔离写定义仍拒绝正式名。

真实只读计划已在161万行旧表上通过：2026-09-18 的旧范围2370行被完整冻结，不再全表扫描。这只是计划预检，不代表补数完成。

## 来源与完整性

按冻结开市日逐日请求 `margin_secs(trade_date=YYYYMMDD)`，保留接口四个字段及全部证券，不自行缩成股票子集或重映射交易所。空响应、达到6000行保守上限、重复完整键和字段／日期异常均拒绝完整，原件保留为失败证据。

每一天先核对旧键。来源遗漏任意旧键时，在发送前拒绝；本轮没有批准删除旧名单行的策略。然后按原批次发送、WAL及完整字段回读，最后核对整日名单。逐批通过后整日仍不符，耐久保存原来源引用，运行及区间锁保留 `IN_DOUBT`，不自动重发或解锁。

后续日期来源失败时，先前已完整核验的日期保留为 `PARTIAL`，可沿原冻结请求恢复并重新核对已验证日期。原日历及日期窗不在恢复时改写。

## 配置和实测范围

writer 使用 `app.sync.margin-secs-write-table`，环境覆盖为 `APP_SYNC_MARGIN_SECS_WRITE_TABLE`。默认回退原 `app.sync.margin-secs-table`，再回退 `java_d030_margin_secs_acceptance`；旧配置仍控制公开读取目标。默认公开读取正式表、写入隔离表的原行为保持。部署若曾覆盖旧读取配置，切换时须明确核对读写两端。

真实单日来源4475行，旧范围2370行，没有旧键在来源中缺失。只读检查不认证原表全部字段值或后续更新。

私有 QuestDB 使用全部4475行冻结来源验证首次写入、旧值修订、公开完整字段读取、范围外保留和第二日来源失败后的原请求恢复。私有旧值、修订、前一日来源和日历是夹具，不算真实多日覆盖。单元测试另验证整日失败留锁、计划后范围内变更被拒绝，以及范围外变化不被当前请求改写。

证据见[阶段核验](audits/2026-10-21-cn-margin-secs.json)。正式补数范围、周期更新及消费者仍未验收，不计正式完成。
