# ETF 目录的正式目标与完整回读

ETF 目录已支持显式绑定原 `etf_basic` 表，并补齐发送前后的全目录核验。默认仍是 `java_d013_etf_basic_acceptance`，本轮没有正式写入或启用周期任务。

```sh
# 当前完整来源和旧目录的只读核查，不创建正式运行账本。
APP_SYNC_ETF_BASIC_TABLE=etf_basic \
./gradlew run --args='check-etf-basic-source --logical-date 2026-10-21'
```

来源固定 `fund_basic(market=E)`，不按存续状态筛掉记录。一次只接供应商完整目录，空响应或达到 15000 行容量上限就拒绝完整，原文先归档。日期参数须换成实际上海观察日，不能用当前目录认证历史快照。

## 正式准入保持什么

正式执行只放行精确同名表 `etf_basic`，原隔离前缀仍可用。隔离建表工具继续拒绝正式名；没有新增正式 DDL、迁表或清理。读目标和写目标共用 `app.sync.etf-basic-table`，根默认值和标准环境覆盖均已测试。

列、YEAR/WAL、作业版本1及数据版本1不变。`timestamp=1970-01-01T00:00:00Z` 仍是固定技术哨兵；`update_time` 是原请求冻结的真实UTC观察时刻，精度为微秒。原物理目标、原冻结参数、旧作业和恢复指纹不重绑。

原命令 `plan-etf-basic-job`、`run-etf-basic-job --logical-date 日期` 和 `run-etf-basic-job --resume-from 原运行编号` 保持。正式模式要求全目录端口；跨观察日恢复会拒绝重抓当前来源，未决运行不自动重发或解锁。

## 怎么认证完整目录

1. 收齐并验证整个来源，才发送第一批。
2. 发送前完整读取原目录，核对原物理对象和稳定WAL，最多30000行，不静默截断。
3. 将本次来源键与不在来源中的保留旧键分开记录。保留旧记录的全部原值及原观察时间，不把它们算进当前来源覆盖，也不自动删除或补造退市状态。
4. 保存全目录耐久意图，按原批次发送并回读。
5. 最后再读整个目录，按完整键和全部字段摘要比较：本次来源的所有行，加上未变的保留旧行。并发新增、重复键、保留行变化或来源值不符均阻断，并保留原锁。

`fullDirectoryVerified=true` 只说明上述键值联合核验通过。本次来源覆盖看 `sourceCurrentKeys`；`retainedLegacyKeys` 不代表仍被供应商确认的当前基金。消费者若要当前来源名单，须使用原凭证里的当前键，不能直接把全表行数当作当前名单数量。

创建全目录意图后发生发送或最终回读失败时，运行保留为未决，不自动重发。旧只读检查和发送确认不能替代人工核对原源文件、原目标和完整目录；本轮没有新增自动解除未决的入口。

## 本轮验证

真实来源2997行，原表完整读取2958行，有3个原键不在本次来源中，另有42个来源键在原表未出现。三个旧键是 `1500201.SZ`、`1500211.SZ`、`5012011.SH`，数字前缀均为7位；含义未被当前来源确认，原值保留，不自行截断或映射。旧行原值另留只读证据，没有修改正式表。

私有 QuestDB 已用全部2997行冻结来源验证首次发布、夹具修订、保留旧行、公开读取和epoch哨兵；空来源不会清空旧目录。单元测试另覆盖并发新增和保留行变更后的原锁保护。私有保留旧行和修订为夹具，不冒充供应商真实修订。
