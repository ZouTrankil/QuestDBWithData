# 核对现有代码和官方样本

状态：已完成。六组各取四个月份，共 24 个真实样本；官方 CHECKSUM 和全部字段解析通过。见[样本结果](../../audits/2026-10-20-btc-archive-probes.json)。新模型与六张新表已落实，旧表和旧请求保留。

## 做什么

现有 Java 入口已经下载现货、永续小时线，校验 CHECKSUM，并处理现货时间精度变化。但默认从 2021-10-01 开始，字段只保存了部分 OHLCV，不能直接当成六组数据都完成。

1. 盘点 `CryptoDataMain`、`CryptoHistoryCollector`、`CryptoPriceMapper`、原队列和实库；旧成功数据与未决任务先保留。
2. 六组数据各取真实样本，覆盖 2024、2025、2026，现货额外检查 2024 年末到 2025 年初。记下 URL、CHECKSUM、CSV 表头、列数、时间单位和可用起点。
3. 定义六组数据的字段、单位、完整键、唯一写入方、目标和来源版本；扩展根 `config/`，让 BTCUSDT、日期、数据类型和周期能单独选择。
4. 写清原生日线与现有小时聚合日线怎么共存或迁移，避免同一个键被两种来源来回覆盖。

## 交付和验收

交付六组样本、字段表、下载范围及现有能力/缺项清单。未取得的样本写明原因；不只构造 URL 就算来源已验证。
