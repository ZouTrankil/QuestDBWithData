# 补新数据和处理历史修订

依赖 01 和需要更新的数据集。状态：首版已完成。增量、来源重试、修订探测、同键修订与原运行恢复已有代码和测试；真实恢复已完成。改键修订先跳过，定时部署待安排。

## 做什么

让采集能长期继续，并发现官方 ZIP 的历史修订，不靠一直向末尾追加。

1. 每轮固定目标截止日，只处理已结束且官方已发布的范围；目标未知不能取运行中不断变化的“今天”。
2. 检查新文件和旧文件 CHECKSUM。月包替换日包时先核对重叠，冲突记录并按明确的新版本处理，不静默覆盖。
3. 原 ZIP 不改；QuestDB 对同键修订绑定原物理表和旧值，核验后推进新运行。改键或删除不自动迁移；研究 Parquet 按摘要保留版本，清单原子切换。
4. 文件下载、标准化、质量检查、正式发布分开记进度。已发未决写入先核对，不能当成失败自动重发。

## 交付和验收

重复同步不增加重复键；模拟官方修订只更新相关范围。中断恢复和失败回滚可验证，未通过的数据不推进正式版本。
