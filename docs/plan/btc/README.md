## 每次任务怎么交付

1. 固定任务 ID、UTC 范围、涉及的数据集和验收用例；先核对工作区现状。
2. 只扩展已有入口与端口。保留旧表、旧请求、原文及恢复账本。
3. 交付代码位置、测试命令与结果、真实验证范围、证据路径和剩余限制。
4. 状态分别写“实现、测试、真实验收、运行部署”，不能只写“已完成”。缺真实来源或环境时保留待验收。
5. 本轮只整理计划，不改变生产协议。后续若改变产物协议、恢复或对外接口，实现时同步主规范并补设计决定。

## 几条不能弄错

- 原 ZIP 全留；标准 K 线保留全部有效字段，不只留七列。来源数值先按原精度保存，再做明确的类型转换。
- K 线逻辑时间用 `open_time`，结算用 `funding_time`；都是 UTC 真实时刻，不统一叫 `trade_date`。已有 `ts` 等字段通过明确映射兼容。
- 键必须包含交易所、币对、产品和周期；价格数据还要区分成交、标记和指数。来源摘要属于版本，不作为躲避同键去重的维度。
- 数据收盘时刻、结算时刻不等于真实可用时刻；下载时间也不能证明历史上当时已知。无可用时间证据时写明研究限制。
- 不改变旧请求、物理目标或恢复归属；结果未决不自动重发或解锁。正式写入仍做完整键值回读、WAL 和稳定版本核对，不能拿 ZIP 校验代替。

旧采集入口的默认起点为 2021-10-01；原生归档增量使用 `app.crypto-data.archive-history-start`，当前默认 2020-01-01。执行时核对所用入口和根配置，不能混用。若新增模块或依赖，按项目要求检查架构、模块边界、配置加载和发行包。改动用相关样本测试，真实六组覆盖另验。本轮已下载和解析 24 个官方样本，并新建六张远端产品表；未改旧表。实际覆盖和缺项看队列及审计报告。
