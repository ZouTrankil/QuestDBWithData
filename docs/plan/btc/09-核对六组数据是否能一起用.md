## Q1：质量清单与字段级准入

已实现质量规则 v3。机器可读报告包含：

| 内容 | 必需信息 |
| --- | --- |
| 检查对象 | 批次或候选批次 ID、数据集、UTC 左闭右开范围、输入文件摘要 |
| 问题 | 稳定问题 ID、业务键或范围、受影响字段、缺口/提前结束/冲突/未知间隔等类型 |
| 证据 | 来源摘要、原运行或审计引用；未知原因明确写未知 |
| 准入 | 受影响用途、拒绝或带标记读取的规则、规则版本 |
| 汇总 | 各数据集覆盖、按用途的共同可用范围、排除数量和原因 |

规则：

1. 来源完整、正式发布已核验、研究用途可用分别记录。没有原账本或正式证据时不得自动认证。
2. 四天成交字段冲突按实际差异字段登记：`2021-01-21`、`2021-04-23`、`2021-12-24`、`2022-04-13`。不能据此自动剔除 OHLC，也不能无依据地判定日线或小时线哪一侧错误。
3. 提前结束的 K 线保留原结束时间；要求完整小时的用途拒收，其他用途显式标记。24 条记录不自动代表完整一天。
4. 缺小时不填价格；合法停市须有原证据。资金费率不按固定八小时生成预期事件，未提供的间隔保留 null。
5. 日小时对账保留当前基线：成交笔数精确相等，其余数值 `rel_tol=1e-12`、`abs_tol=1e-8`。报告记录容差和版本；更改时用原始数值复核，不通过放宽容差消除冲突。

验收：缺小时、提前结束、字段冲突、未知间隔各有固定样本；严格读取所需字段被限制时必须拒绝；探索读取返回问题和排除统计。相同固定输入与规则生成相同业务检查结果。

## Q2：明确关联时间与用途

已实现。原两小时沿用价保留为兼容模式，`synchronous` 显式要求同一完整小时。

- `read_batch(..., purpose="funding_synchronous")` 执行固定报告中的关联规则；默认 `purpose="raw"` 只约束所读原字段，不因缺价否定费率本身。同步价差用途：四种价格必须来自同一个完整小时，且该小时已在事件前结束。缺任一价格则报告缺项，不分别沿用不同小时。
- 允许沿用价的用途：显式选择，输出每侧 `open_time`、`close_time`、价格年龄和是否沿用。阈值读取根配置，保留当前两小时作为兼容默认，不隐藏在新接口里。
- 最终结算费率用于事后结果；没有历史可用时间证据时，不宣称它可用于结算前决策。`observed_at` 不改名冒充 `available_at`。
- 只有事件时间和最终修订值的批次明确标记不保证历史 PIT；不为通过检查伪造发布时间。

验收：事件恰好落在小时边界、当前小时未收盘、前一小时缺失、两侧价格来自不同小时、超过允许年龄、范围首日缺前置行情，均有预期结果。保留当前兼容行为的测试，新严格模式单独测试。
