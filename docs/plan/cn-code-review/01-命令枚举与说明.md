# 命令枚举与说明

依据：[StockCommands](../../../markets/cn/data/src/main/java/com/zoutrankil/data/cli/StockCommands.java) 与当前命令注册实现。核对日期：2026-10-20。

## 要解决什么问题

已确认的是命令元数据分散：`StockCommands` 在 `COMMANDS` 和 `execute()` 的字符串分支中分别写命令名，缺少随命令维护的中文用途。检查同步代码时，难以直接分清规划、真实写入、恢复和发布收尾命令。

例如 `run-daily-job` 与 `finish-stk-suspend-publication` 的作用不同，只看名字不能知道各自前置条件。后续新增命令还需同步维护注册与处理分支；这是维护风险，当前没有证明已经存在漏注册或错误分发。

建议做可维护性改进，优先级低于同步正确性。枚举只是实现手段，目标是一个地方能查清命令名、用途和处理入口。

## 怎样算解决

能从命令目录直接看到每项中文用途；增加命令有明确的登记位置；注册集合与处理分支保持一致。旧命令仍可原样执行，未知命令仍被拒绝，不以“已经改成枚举”单独作为完成条件。

## 分析与结论

建议改。`StockCommands.COMMANDS` 是字符串集合，执行分支又维护相同命令名，中文用途也没有跟命令放在一起。用枚举保存命令字符串和 `desc`，更容易查找、补说明和发现遗漏。

枚举属于 CLI 元数据，不是同步任务或表模型。`plan-daily-job` 是命令，`data.daily` 是持久化任务 ID，不能混用。保留 `CliCommandFamily.commands()` 的 `Set<String>` 接口，对外命令仍使用原字符串，不使用 enum.name() 替代。

先整理股票命令，不建立覆盖所有市场业务的巨大枚举。枚举常量加中文注释，`desc` 用于帮助说明；现有参数约束仍留在执行入口。

代码入口：[StockCommands](../../../markets/cn/data/src/main/java/com/zoutrankil/data/cli/StockCommands.java)、[CliCommandRegistry](../../../markets/cn/data/src/main/java/com/zoutrankil/data/cli/CliCommandRegistry.java)。
