# 补充策略研究所需数据

日期：2026-10-20。性质：必要的数据准备任务。合并原“04-目标 ETF 日线数据就绪与缺口处理”，避免重复补数。
依据：[需求原文](../../../markets/us/plan.txt)、[现有数据能力与验收记录](../../us-market-data.md)。本任务要实际补齐并验收可用输入，不只交付盘点表。

## 为什么必须做

策略研究需要连续且可追溯的历史，几天样本或表的最大日期不能支撑回测。当前验收记录不能证明本次全部目标都已有足够日线；需在实际环境核对已有数据，保留可复用部分，再补确认的缺口。

这份任务应先于真实回测执行，但只负责数据，不调度其他文件，也不等待组合权重确定后才开始采集。

## 补哪些标的

| 用途 | 标的 |
| --- | --- |
| 七基金组合 | VOO、QQQM、AVUV、SPMO、DBMF、RSST、SGOV |
| Hi5 视频摘录版 | RSP、IWY、MOAT、PFF、VNQ |
| TQQQ 来源策略 | TQQQ |
| 比较基准 | SPY、QQQ |

共 15 个不同标的。基准也要验收，不能只补策略持仓。Hi5 新版或 TQQQ 原始规则若确认另有信号资产，按明确来源补登记所需数据，不猜标的或自动扩大到全市场。

## 拉取多长，怎样算足够

- 默认历史起点为 `2006-01-01`，与现有 US 历史目标一致；各基金从该日起或真实首次交易日起取数，以较晚者为准。供应商更晚才有数据，属于需要记录/补验的来源缺口，不能把供应商起点直接当上市日。
- 本次运行先按 `America/New_York` 固定一个截止交易日。沿用现有来源完成规则：纽约 20:30 前不纳入当天，之后才允许纳入当天，再按实际开市日选择截止日。保存这个日期，采集中断恢复不得随系统日期滚动。
- 拉取目标区间内全部真实日线，不采用“随便最近 500 根”或“拉够行数就算完成”。约五年可作较长历史标的的诊断窗口，不是上市不足五年的基金必须补满的要求，也不替代完整历史目标。
- 信号有回看窗口时，评估开始日前必须有足够的真实预热数据。例如需要 N 个交易日，核验至少 N 个所需有效观测；不以 N 个自然日代替。若起点前材料不足，缩短可评估区间并说明原因，不造预热数据。
- 同时输出每个标的的完整可用范围和各组合/比较对象的共同有效范围；检查区间内缺口，不只取首尾交集。较新基金会限制共同样本期，如实展示，不能用 QQQ 替代 QQQM 或合成上市前基金收益。

## 具体要有的数据

- 原始及调整 OHLCV、现金分红、拆股因子、币种、来源、原文摘要和取得时间，复用现有 `us_equity_daily` 契约。
- 基金身份、首次交易证据及相关公司行动；区分代码复用、未上市、退市、休市、零量报价和来源缺失。
- 对应历史区间的纽约交易日历和时区规则。现有 2026 年会话日历不能单独验收约二十年的历史；历史日历证据不足时明确限制。
- 收益记账需要的分配日期信息应单独核对：现有除息日分红字段不能冒充支付日。能取得则保留明确来源，取不到记录缺项；任何近似由研究配置显式声明。

首期补日频输入，不默认拉分钟或逐笔。额外信号序列与频率只有在规则确认确实需要时才纳入。

## 怎么实现

复用 `UsMarketDataMain`、US 来源映射、原队列和正式发布能力。先只读核对实际表、来源账本及未决状态，再复用已验收价格和原始响应；已有入口不能独立选择目标与日线范围时，补最小有限选项，避免把新增 ETF 日线与整年分钟任务捆绑。

Java 继续作为来源同步和 QuestDB 唯一正式 writer，Python 只读研究。配置只维护根 `config/`，请求继续遵守原持久配额、来源隔离与有界重试。未决写入先核对原运行，不新开任务重发、不自动解锁，也不覆盖旧成功或失败证据。

业务日期用纽约 `LocalDate`；采集、可用时刻用 UTC `Instant`。日线 UTC 零点是日期编码，不加 8 小时或按纽约时区移成前一天。

## 要达成的效果与交付

1. 研究代码能按基金、日期和来源只读取得已经验收的日线，15 个标的均有确定状态；数据不足时给出具体缺日或字段原因。
2. 交付覆盖清单：标的身份、目标起止、实际起止、有效行数、缺日/原因、公司行动完整性、预热是否满足、来源版本及证据路径。
3. 交付各自历史和共同样本期清单、可复用取数方式、补数调用配置及原运行验收凭证。
4. 已有数据不得因本次补数丢失或换供应商覆盖。不能取得的历史保留明确缺口，不宣称全部完成。

## 怎样验收

- 逐标的核对实际身份、预期日期与完整业务键，不用最大日期、行数、HTTP 成功或进程退出码单独证明完成。
- 目标范围完整字段回读，来源/目标版本及物理对象稳定，WAL 已应用后才推进；已有成功数据继续可核对。
- 补数涉及的正常、重复运行、修订和中断恢复按原协议验证；修改采集代码时执行相关 US 测试，影响模块时补边界、架构和发行包检查。
- 回测开始前能明确判断每个所选标的及信号的区间、字段和预热是否满足。缺输入的范围标不可运行，不填造成交价格。
