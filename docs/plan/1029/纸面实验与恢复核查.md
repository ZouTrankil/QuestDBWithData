## 已有 E0 基线核查

[固定配置](experiment-config.json)和 `tools/plan_1029_research.py` 的 E0 使用 SPY、QQQ、IWM、TLT、GLD 等权，初始 100000 美元，月初交易日前一完整收盘决策，下一交易日调整开盘价成交；单边费用 5bps 加滑点 5bps，碎股、零现金收益；末日收盘强制卖出并付费。调整价仅是总收益近似，历史时点可得性未证实。日历须来自冻结的纽约交易时段，而非工作日推算。

## 连续纸面 E0

`tools/paper_etf/e0.py` 是独立 SQLite 账本，无账户或网络接口。首次运行和每月第一个提供的交易日按开盘调整为五只各 20%，其余日持有；不做回测末日清仓。每个交易日保存输入文件 SHA-256、数据版本、信号和成交时间、目标权重、模拟价格、交易额、费用、现金、持仓及收盘净值。费用含假设滑点，调整价和碎股是研究近似，不代表可实际成交或现金分红。

输入 JSON 须由使用者先冻结和核验：`data_version` 是非空版本标识；`sessions` 是按交易日递增的完整纽约交易日历，包含前一交易日，逐项包含 `date`、带时区的 `open_at`、`close_at`，以及 `prices`：五个标的各有正数 `open` 和 `close`。价格须是同一版本调整价格。收盘后运行：

```bash
python tools/paper_etf/e0.py --db var/paper-e0.sqlite --input /path/to/frozen-input.json --day 2026-11-02
python -m unittest tools.tests.test_paper_etf_e0 -v
```

指定新的独立账本；输入及账本不要提交仓库。之后按日历逐日执行，相同日期及相同输入重复调用只返回原记录；输入更改或跳日会拒绝，需人工检查并另建实验。程序依赖使用者提供完整、正确且已收盘的交易日历与价格，不验证来源真实性、公司行动、时区与日历完整性，也不自动获取或调度数据。数据版本和原文件应一同保存；不可把模拟测试当作真实连续实验。
