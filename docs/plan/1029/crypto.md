# BTC／ETH：启动数据范围与验收

## 1. 启动范围

BTC 优先使用 Binance 原生表；现货日频趋势先行，小时线与资金费率用于后续增量实验。ETH 先使用通过验收的 Binance 现货行情，Bybit 作为来源对照，不混合拼成一条价格序列。

以下来自用户的 QuestDB HTTP SQL 只读查询结果。本次整理未重查数据库；具体字段、查询快照时间和数据库版本仍需后续执行任务确认。

## 4. 必做检查与验收

| 检查 | 具体内容 | 验收标准 |
|---|---|---|
| 表与字段 | 核对交易所、市场、币对、合约类型、频率、时间、OHLCV、费率单位 | 确认 BTCUSDT／ETHUSDT 的实际产品；区分 USDT 与美元计价 |
| 唯一键 | 行情按交易所＋市场＋标的＋频率＋时间；资金费按真实事件身份 | 各分组重复为零或有可追溯处置；不随意删除不同类型的结算事件 |
| 24/7 完整性 | 建立 UTC 小时／日时间轴，列出缺失、重复、未完成 K 线、零量及维护例外 | 每个启动窗口有明确可用区间与异常表；数量相等不能代替逐时间检查 |
| K 线语义 | 核实时间是开盘还是收盘、时区、日界；用完整小时线聚合核对日线 | 开始时间为 08:00 的小时线不能在 08:00 使用其收盘价；日线须等完整结束 |
| 价格和量 | OHLC 关系、非有限值、异常跳变、负量；区分基础币量与报价币量 | 不把跨交易所量口径直接混用；极端行情保留并解释 |
| 多表对齐 | 使用各自真实可见时间与共同有效区间；统计连接丢失的时点 | 不以静默 inner join 隐藏缺口；不前填行情制造交易或前填资金费伪造结算 |
| 资金费 | 实际结算时间、费率小数／百分数、方向、历史周期、名义价值计算 | 逐事件核算；已结算费率只能在其公布后作为未来信号 |
| 标记价与指数价 | 明确它们用于估值、风险及基差特征，不是可成交价格 | 成交仍用对应市场交易价格；小时标记价不冒充结算瞬间精确标记价 |
| 双源与数据库 | 原生 BTC 与跨资产表对照；核实 WAL 异常与数据快照一致性 | 差异有解释、来源优先级固定；不能静默替换来源补洞 |
| 成本与风险 | 双边手续费、滑点、数量步长、最小订单、保证金、资金费和现金收益假设 | 每笔成交及资金费可复算；杠杆清算结论不能由小时收盘价单独证明 |

资金费率可能调整结算周期，不能永久写死每八小时。正费率通常是永续多头付给空头；事件时点、持仓资格及最终费率按当时规则确认。[Binance 官方说明](https://www.binance.com/en/support/faq/detail/360033525031)

## 5. 启动窗口与缺口处理

- BTC 现货单表实验可用通过验收的完整日线至 2026-10-24；多表实验暂以 2026-10-23 为共同截止日期，再处理内部缺口。
- ETH／BTC 轮动使用同交易所、同频率、同市场的已验收共同区间，库存上限为 2021-10-01 至 2026-10-25。预热期不计入成绩。
- 对比实验必须采用同一评分区间。缺失时先定位原因，可按来源修补或选择连续区间；跨缺口的持仓、估值及恢复规则事先写清，不能把未知损益跳过当作零。
- BTC 提议以 2020—2023 年开发、2024 年起留出；ETH 提议以预热后至 2024 年末开发、2025 年起留出。任务冻结时确认未根据留出期表现调参；否则调整方案并标明原因。
- 不因为末尾少一两天就延迟历史实验，不把日线与小时线同一行情视作独立样本。
- 资金费对冲缺少精确结算估值时，可以报告明确近似的初步研究，但不能标为精确现金账本或实盘验收。

## 6. 最小补充与项目适配

启动优先补已识别的历史缺口、字段说明和交易规则。现货实验不依赖 mark／index；只有资金费对冲实验才要求对应输入通过验收。暂不采盘口、链上指标、新闻、大量币种或跨所高频报价。

项目 [crypto Loader](../data/crypto/loader.py) 与 [案例](../case_studies/crypto_perps_funding/README.md) 使用溢价指数及多币种配置。真实结算资金费率、现货—永续价差、标记价—指数价差、官方溢价指数是不同对象，字段不能互相冒名替代。后续按单币／双币实验作最小适配，不称为完整复现原案例。
