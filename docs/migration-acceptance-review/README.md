## 2. 什么算完成

分别记录三个状态，不用一个“完成”混在一起：

1. `implementation_status`：planned / implementing / implemented。
2. `verification_status`：not_run / blocked / failed / verified。真实外部链路验收通过才能 verified。
3. `human_review`：pending / changes_requested / accepted，由用户填写。

**单数据迁移完成 = 实现完成 + 适用公共标准全部通过 + 本对象专项标准通过 + 真实证据齐全 + 用户 accepted。**

“允许切换生产”单独登记 `cutover_status`，需要确认全量覆盖、唯一写入 owner、调度、下游兼容与回退；小样本 verified 不能直接代表生产接管。未准入、无需迁移或已退役用独立处置状态及用户决定，不计为迁移成功。字段/规则 N/A 必须有理由和用户确认，不能由开发者自行删减标准。

## 3. 公共验收标准（每个对象继承）

| 编号 | 要交付什么 | 通过条件 |
|---|---|---|
| C01 契约 | 来源/owner/caller、字段映射、单位、空值、枚举、主时间、业务键、物理键、写入模式、依赖、版本 | 每个目标字段都能追溯；未解决的键/时区/来源问题为 0；旧字段删除或含义变更须 review |
| C02 模型 | 来源 DTO、业务模型、存储映射、完整 Key | 日期与时刻分别建模；UTC/业务时区、秒/毫秒/微秒/纳秒明确；业务日期往返不偏移；非法值不能默默变 0/null |
| C03 Schema | 现状差异、Flyway 迁移或已有对象接管方案 | 隔离环境新建/升级/重复启动可复现；列、分区、WAL、去重键和依赖匹配；已有表不盲目重建；未变更 DDL 也提交比对结果 |
| C04 来源完整性 | 有限请求、账号能力、页长、结束条件与源响应证据 | 有效请求范围完整；截断、重复页、游标停滞、超时不得成功；真实空与请求失败分开；不支持的模式明确拒绝 |
| C05 写入与幂等 | typed 分批写入、规范化字节预算、ACK 与可见性验证 | 非空来源写入后完整键/全部契约字段核对；同键同值重跑不增行；同键修订按已冻结策略更新/留版本；重复/缺失/多余键为 0 |
| C06 读取 | 按键/区间、投影、游标、空结果、错误返回 | 多页遍历与独立查询的完整键集合一致，无漏行/重复；无界读取拒绝；未授权字段/排序拒绝；View/MV 直写被拒绝 |
| C07 增量与恢复 | 有界 bootstrap/backfill、已验证覆盖/检查点、修订策略、恢复 | 检查点只在验证成功后推进；故障后已验证片可证明复用；重新启动恢复结果等同完整运行；纯快照/事件来源说明替代身份，不伪造历史增量 |
| C08 故障治理 | 限流、重试、取消、互斥、未知写入对账 | 有界重试且每次请求计费；取消保留证据；并发冲突拒绝；kill/超时后的状态可识别，未知提交不自动重放，并有可执行人工对账流程 |
| C09 质量与可用性 | 适用的完整性/唯一性/时效/值域/一致性/PIT规则 | 给定窗口和证券集合有覆盖报告；允许缺失必须逐因解释；关键质量失败阻止下游 ready；没有执行规则不能算通过 |
| C10 管理与交付 | 注册定义、plan/run/status/history/cancel/resume，组合接入与运行文档 | plan 无写入；配置与实际执行一致；失败退出码非零；run/attempt/slice 可追踪；所有正式写入入口遵守同一控制面 |
| C11 对照 | 冻结同一来源输入后比较 Python 和 Java | 完整键及全部业务字段一致；Python 已知错误单列差异，经独立业务依据与用户确认；不是只比行数/抽几行 |
| C12 证据 | 代码版本、运行请求、规范化源、目标身份、查询/参数、差异报告、故障记录 | 证据可定位可复现；声明真实来源与 fixture；没有可用来源则 blocked，不拿 fixture 替代真实验收 |

数值规则：字符串/代码/日期/整数/枚举/空值必须精确匹配；浮点容差按**字段**事前冻结并说明依据，默认不允许未解释差异。单位转换和精度截断必须显式；无法保留精度时应拒绝，不默默舍入。不要为通过验收临时扩大容差。

## 4. 最低验证场景（按对象类型适用）

以下为建议最低门槛，需要用户 review；不是线上全量完成的保证。

- 日频数据：至少 3 个有效交易日 × 3 个适用证券/合约，跨一个月份边界，并覆盖一个非交易日。市场总体表按其天然单行/多维结构验收，不强造证券维度。
- 月/季频数据：至少 3 个已发布期间，覆盖跨年；财报额外覆盖首次发布与修订。数据不足必须说明原因，不能静默减样本。
- 资料快照：一个完整受控来源快照，覆盖适用状态；验证新增、变更及消失/退市处置，不能简单把“来源本次未返回”当删除。
- 稀疏事件：至少一个非空真实窗口和一个证实为空的窗口；覆盖同日多事件或同键修订边界。真实稀有修订不可得时记录证据缺口，fixture 只证明逻辑。
- 文件/事件导入：一个可溯源真实脱敏批次，另验证重复、坏行、乱序、断点；文件 hash/事件身份必须参与幂等。
- 衍生表/View/MV：至少一个非空冻结上游窗口，独立计算/查询核对全部输出；验证上游缺失、迟到修订、依赖版本变更和输出失效，不要求向 View 直接写数据。
- 运行元数据：由真实或受控端到端运行生成，验证成功、失败、部分完成三种状态；不能通过直接插入 success 行证明链路。
- 每个可写对象：非空首跑、同范围重跑、适用的下一窗口、异常中断恢复；写入/回读未知状态不得记 verified。破坏性故障验证仅在隔离目标中执行。

## 5. 生产接管门槛

- Review 冻结历史覆盖范围与补齐截止点，完成该范围对账；明确新增/退市/停牌/停发等合法缺失。
- 建议至少 5 个实际调度周期并行对照，包含一次受控恢复；低频数据按真实发布周期约定，回放证据单列。
- Python 与 Java 不对同一正式目标同时写入；对照阶段使用隔离目标或单 owner。切换记录包含停止旧调度、新调度启用、告警责任人及回退步骤。
- 明确同步 SLA、源发布时间、时区、允许迟到时间、最大请求/行/字节/耗时预算；数值必须在该对象验收开始前冻结，不默认所有表同一标准。
