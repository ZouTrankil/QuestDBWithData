# 主策略覆盖键编码分版

v1 键摘要只包含值。同一组值换了字段名后仍可能得到原摘要，不能据此证明新字段协议已核验。

v2 用 `StrategyInputSchema` 明确声明来源角色、业务键名和编码版本。单标的日频键使用 `trade_date/instrument_code`；持仓保留 ETF、成分、公告日和报告期末；日历使用 `calendar_date`。日期编码为规范 ISO，不能把时间戳或紧凑日期直接混入键。

v2 在原有排序、长度前缀编码前加入版本、角色和字段名。空来源也有自己的摘要，旧 v1 摘要不能冒充 v2。组装和核验都按明确版本执行；未知版本、缺少键声明或版本号被单独替换都会失败。v1 的原编码保留，独立字节向量对照通过。

v2 必须有新的独立批准输入及 SHA-256；原文件、证书、历史证据和账本仍逐项核验，不覆盖旧材料。测试使用临时目录里的单元样本，不是生产源完整性证明。

本批只完成覆盖协议核心。读取器归一化、历史时点、新产物和 Python 读取端尚未贯通，正式配置不在本批切换。135 项主策略回归通过，架构、模块边界及发行包通过；全项目 1975 个 Java 文件格式、import 和字面量检查通过。未执行正式发布或数据库迁移。
