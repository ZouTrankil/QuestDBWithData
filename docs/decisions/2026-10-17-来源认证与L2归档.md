# 来源认证和 L2 归档

本次补齐财务接管、历史输入及归档能力，保留现有目标表、运行账本和未决恢复协议。

- 五条财务源由 A 股 Java 数据进程写入，复用共享执行器。范围必须显式给出；日批默认关闭，有限 CLI 和主策略不启动日批。公告日和报告期继续按业务日期处理。
- 来源凭证只证明原账本中已经核验的冻结请求。评分覆盖及正式因子认证还需要独立批准范围，不能从实际结果反推预期范围，也不能把 partial 回执改成完整。
- 历史评分按生效日期、当时可用时间和真实决策时刻选择资料。历史原件缺失时停止，不用当前名称、行业或修订值补过去。
- L2 SQLite 升至 schema 4，兼容读取并迁移 schema 2、3。Parquet 继续保存类型化结果和累计状态；SQLite 只增加归档引用和计数，不改成结果 BLOB 存储。
- 日归档在停采后显式执行，逐批核对合并结果，先发布文件并提交 SQLite 引用，再删匹配的旧文件。保留当前恢复批次、混日批次及原始接收日志。读取历史使用已提交文件清单，避免漏读归档或重复旧批次。
- 私密值保留在根配置目录的本机覆盖，Git 忽略且不打包；公开 YAML 继续集中管理各 profile。没有更换现有凭据。

真实财务写入、独立范围及历史原件、L2 全天实采和成对备份恢复仍需单独验收。短合成负载和单证券只读响应不能代替这些结果。

操作入口见[财务同步](../financial-sync.md)、[来源组装](../strategy-source-coverage.md)、[因子认证](../factor-source-certification.md)及 [L2 部署](../../deploy/l2-live/README.md)。
