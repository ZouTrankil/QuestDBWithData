# 用两个父工程收拢模块

业务代码只保留两个顶层父工程：`platform` 放公共能力，`markets` 放市场模块。子模块继续隔离框架、数据库驱动和运行入口，模块数量不因目录归组而减少。

| 原模块 | 新目录和 Gradle 路径 |
| --- | --- |
| `data-core` | `platform/core`，`:platform:core` |
| `runtime-support` | `platform/runtime-support`，`:platform:runtime-support` |
| `data-engine` 及子模块 | `platform/engine`，`:platform:engine` 及子路径 |
| 公共 `data-app` | `platform/app-support`，`:platform:app-support` |
| `market-cn` 及子模块 | `markets/cn`，`:markets:cn` 及子路径 |
| `market-us` | `markets/us`，`:markets:us` |
| `market-btc` | `markets/btc`，`:markets:btc` |

## 父工程做什么

`platform`、`markets` 只使用 Gradle `base` 插件，不放源码或业务 jar。父工程的 `assemble`、`check` 和 `build` 聚合所属子模块。`platform:engine`、`markets:cn` 保留原有 Java 代码，同时聚合其子模块的构建检查；它们的 `test` 仍只运行本模块测试。

根工程继续负责跨模块架构检查、兼容启动命令和发行包。公共配置仍在根 `config/`，产物仍在根 `build/`，完整模块路径用于隔离输出。父模块 `clean` 不删除子模块输出。

## 不涉及数据迁移

Java 包名、配置 profile、表名、数据版本、Job ID、SQLite 位置、来源覆盖、时间规则和恢复协议保持原样。A 股常驻入口继续按配置托管 Batch，主策略与实时 L2 仍独立启动。美股和 BTC 没有新增采集能力。

显式 Gradle 模块路径和内部 jar 名称随归组改变，调用方需使用新路径；根级启动命令和发行包名称保留。模型生成器、架构检查和依赖基线的项目路径同步更新。历史设计记录保留原路径，当前使用以主规范为准。
