# BTC 官方原生归档

六组 Binance 原生数据放远端 QuestDB 的 `btc_spot_1d`、`btc_spot_1h`、`btc_perp_1h`、`btc_funding`、`btc_mark_1h`、`btc_index_1h`。

旧 `crypto_ohlcv`、旧任务和恢复队列不变。它混有小时聚合日线，不能让官方原生日线覆盖同一个旧键。

Java 唯一写入。新归档队列在原数据根目录的 `binance-vision/archive-queue.sqlite3`；正式发布继续共用原 `sync-ledger.sqlite3`、发布锁和完整核验。新旧下载共用原请求预算。

K 线用 `open_time`，资金费率用 `funding_time`，均为 UTC 事件时间。现货从 2025 年起用微秒，期货仍用毫秒。资金费率保留来源间隔和毫秒偏移，不补成整点。标记价、指数价不保存占位成交量和计数。

每个 ZIP 保留全部原字段与原精度；QuestDB 的价格和费率用 DOUBLE，成交笔数用 LONG。`observed_at` 只表示本次取得时刻，不声称历史上当时已知。

归档缺失、解析异常先记录并跳过。发送前保存 `PUBLISHING`；异常后保留原状态和账本，阻止该数据集自动重发，其余组继续。官方历史修订和未决恢复须核对原运行，不能重置队列掩盖问题。

2020、2024、2025、2026 年共 24 个真实样本已校验和解析。首批六组 2020 年 1 月已完成正式发布、完整回读和 WAL 核对；全历史另看队列结果。

正式发布可按年合并多个已校验文件，bundle 固定各文件原文、摘要、范围和质量明细；队列按文件分别记结果。缺小时、提前结束及已识别的坏空占位行不能变成完整月份，使用 `PARTIAL_VERIFIED` 保留边界。源文件完整与业务时间轴完整分开，原请求和未决恢复不变。

资金费率公开历史 API 不提供结算间隔。`btc_funding` 的定义 v2 允许这一列为空，物理表、键和旧 v1 prepared 不改；月包已有间隔不清空。截止月由 API 回补，达到上限或异常响应不作为完整来源。2026-09-30 的三次事件已核对归档与 API 的时间、费率一致。

历史同键修订先核对原成功运行和现有全字段值，再通过 `publishToOriginalTarget` 绑定原物理目标发布；这个入口不建表，目标重建直接拒绝。原默认发布入口及旧请求保持不变。新增或删除业务键需要单独范围迁移，先列待处理。
