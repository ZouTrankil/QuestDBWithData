# 回购与大宗多重记录范围替换

回购和大宗采用显式 v2 范围快照，不能用原键直接 UPSERT。来源没有可靠事件编号，完整行摘要只校验内容，不能充当稳定业务身份。相同内容出现多次也必须保留。

来源使用同市场独立的有界快照client并归档原文，不放宽共享SourceCollector的重复业务键检查。

原列及 YEAR/WAL 保持，新增 `snapshot_ordinal`，去掉数据库去重。公开键为证券、来源日期、范围内序号；序号只属于当前快照，不作跨修订事件对齐。公开分页绑定物理对象和稳定 WAL，每页前后重新核对版本，防止版本读取与 SELECT 之间发生整表切换。

正式写入必须走 Java 的全表有界 staging/backup 发布，复用原同步账本、全表锁和耐久发布日志。先完成全部来源及 stage 页核验，再保存正式重命名意图，切换后完整回读新旧对象。旧表迁移必须明确选择，保留原 backup 及原请求绑定。新旧物理对象不能相互冒充。

按来源日期替换整个范围，完整保留范围外旧行及重复次数。回购截止日可空；大宗同值多笔保留为不同序号。范围内撤销和修订通过整窗重建实现。旧范围非空而来源为空时继续阻断；合法空范围另留原文证明，不补造事件。

原生 MV 依赖须另做切换及刷新，不能默认跟随重命名。未决发送不重发，未决发布只核对原stage、backup、原文和页凭证；源记录或物理对象变化均保持锁。当前显式恢复仅续接已完整核验的原重命名，部分stage发送仍须人工核查，不宣称全故障自动恢复。

实际命令、预算和限制见[同步说明](../snapshot-event-sync.md)。本轮只做代码、只读来源和私有实例验收，没有正式切换或日批接管。
