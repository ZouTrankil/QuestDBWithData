# 资料公告有限接入与旧键保护

本批复用来源契约和正式同步账本，为 11 张资料、公告表增加有限 owner；`balance` 接现有财务执行器。不改表、不自动接管远端 writer，也不调整原冻结请求。

正式资料表沿用 YEAR/WAL、业务键和日期载体；`fut_basic` 保留 epoch 哨兵，观察时刻单独冻结。主营正式 `bz_code` 显式用 VARCHAR，旧 Batch 的 STRING 契约不改。异动 owner 同时提供原 v2 公告日读取映射和新 v1 物理写入定义，取消重复的只读注册。

合约当前目录和当前披露计划都可能不再返回原表旧行。新来源非空时保留旧合约、旧公告版本，把本次来源键与保留旧键分别记录，最终核对两者全部键值。认证只覆盖本次来源请求，不能证明旧行的原始来源完整或历史挂牌范围。来源为空且目标非空仍阻断。

事件表不套这条保留规则：分红重复键、主营 P/D 同键、增减持同键异区间或源中消失旧键都先阻断。真实检查已经遇到这些问题；没有修改去重键或默选一行。

`balance` 请求 `balancesheet`，固定 `report_type=1`，复用修订择优、持久预算和跨日队列。旧 `update_time` 按真实 UTC 微秒原样保留；新行没有该技术时刻时保留 NULL，不把它补成公告日。旧五表的请求和定义内容保持原样。六表日批仍默认关闭；已有五表队列不能借升级偷偷改成六表，先按原运行处理，旧目标摘要不符时继续阻断。

仍需单独处理：荐股键缺券商、回购多方案和可空键、大宗交易同值多笔、黄金日线缺去重键、筹码数组端口、提示来源契约、持仓排名非空证据。这些仍是开发或设计缺口，不归为全体来源不可得。
