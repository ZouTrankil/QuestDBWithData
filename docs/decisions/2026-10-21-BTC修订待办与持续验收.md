# BTC 修订待办与持续验收

本次补齐计划 08—10 的验收缺项，不迁移正式表、旧请求或原写入账本。

## 跨期待办与缺证拒绝

`binance-vision/revision-review.sqlite3` 保存全部修订探测和来源重叠冲突报告的路径、摘要及待办。没有扫描到旧月份、出现新的 `UNCHANGED`、删除报告，都不能解除原阻断。

普通 ZIP 同键修订只有原 Java 修订记录、成功账本、冻结请求、prepared、回执、原件及当前任务继承关系都匹配才可解除；恢复完成还需独立恢复证明。跨来源重叠冲突继续显式复核，不借用普通 ZIP 修订成功来认领。

发布前及切换指针前检查待办。当前版本严格读取遇到相关待办也拒绝；显式选择固定历史批次可以读取，但返回限制。跨机器没有原审查材料时明确标记不可用，不声称掌握最新官方修订状态。

正式认证先从冻结请求确定相关日期范围。相关成功运行缺 prepared 或回执即拒绝；请求中的 prepared/source 摘要必须一致，不能跳过缺证运行再用旧值认证。无关日期的缺证不扩大阻断。

## 质量规则 v3

批次清单仍为 v1，质量规则新增 v3；v1/v2 固定批次保持可读，不补字段冒充 v3。

资金费率关联只从候选 Parquet 计算，逐事件保存前一完整小时的四侧价格、真实结束时刻、价格年龄、来源摘要和缺项原因。`purpose="funding_synchronous"` 执行该证据；默认原字段用途保留费率本身的可读性。最终结算费率仍不保证结算前已知，历史 PIT 限制不变。

空数据库查询沿用实际列信息构造类型，不复制字段字典。空结果保留 Schema；零行导出标记 `EMPTY_OBSERVED`，不据此证明合法空来源或推进正式完整状态。

## 排程与七日观察

根配置增加 UTC 首次时刻、重试间隔和当日次数。默认 UTC 01:00 首次，失败每三小时续跑，最多八次；每次固定同一个前日截止。成功后当天不重跑，进程重启不清零次数，未完成报告也占一次尝试。原日更锁、正式发布锁和持久请求预算继续生效。

安装器在原进程运行时拒绝替换排程，不能为更新任务终止原 writer。排程配置或 macOS 时区改变后须重新安装；当前仍是用户级部署。

观察按真实运行日去重，要求截止日是该运行日的前一日。历史补跑、同日重跑、未来或倒置时刻、失败和缺新版证据的周期不计成功；同时核验固定文件和最新目标批次。七天真实经过前不得宣称通过。每轮自动刷新观察结果，失败不能保留旧的绿色结论。

备份在临时副本验证 SQLite、修订报告引用和 API 原响应，文件及目录持久化后才发布。原绝对路径只用于隔离映射，仍不把副本当成第二个正式 writer。
