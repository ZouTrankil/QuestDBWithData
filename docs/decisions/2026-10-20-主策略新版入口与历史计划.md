# 主策略新版入口与历史计划

独立发布器支持 v2 后，应用仍只生成 v1 面板，周计划也写死旧日历列。此次接通 CLI/Web 的版本选择，并修复历史计划对旧列的依赖。

`MainStrategyDataService` 按已批准覆盖清单选择输出字段。评分器仍使用原训练特征和权重；v2 帧只发布标准身份，夹带旧证券或汇总身份列直接拒绝。

更新评分别名前调用市场包 `preflight`，用实际发布相同的有界日历、候选键、行情和市场状态校验。预检只读，不建目录或写文件；它不能代替提交时的来源重查、文件摘要与 SQLite 事务，也不能保证后续文件系统调用不失败。完成证据仍需同时包含评分对和市场包。

周计划读取根据原评分运行的 schema 选择 `cal_date` 或 `calendar_date`，不从当前配置或字段是否存在猜版本。权威计划格式本身未变，CanonicalPlanJson、SQLite 旧 schema、摘要和原评分绑定不升级。实际测试在日频别名推进到另一版后回读原 v2 周计划，确认计划身份、原证据和幂等导入不变。

旧 Batch 请求没有冻结新版输入协议，暂时明确绑定 v1；配置换成 v2 会在评分计算与产物写入前拒绝。新版 Batch 需要将协议固定进新请求及恢复校验后再接入，不能靠本次入口改动自动升级旧任务。

151 项主策略回归、架构、模块边界和主策略发行包通过。没有生产批准方案、训练文件、历史原件或独立完整参考，未执行生产评分或正式物理迁移。代码接通不等于真实环境验收完成。
