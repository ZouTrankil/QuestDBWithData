# 交易日存储布局分版

先保留旧布局，再显式接入新布局。`etf_adj` 的旧端口把 `timestamp` 写死在预检、范围、完整键回读和日期盘点中；只改 DDL 会让原任务读写失败。反过来按实库“碰到哪列就用哪列”，又会让冻结请求的版本失去意义。

`CnTradeDateLayout` 只允许已核定的六个对象。v1 保留原来的 `timestamp/ts`，v2 选择 `trade_date`；利率、公告、技术 epoch 和待核对象不能套用。它只选择布局，不转换日期、不加八小时，也不改变类型精度。存储布局 v2 与主策略输入协议 v2 是两件事。

本批只接通 `etf_adj`：

- 契约、隔离 DDL、范围查询、写前预检、完整键/整日回读和类型化读取共用显式布局。
- v2 仍使用 TIMESTAMP 微秒、UTC 午夜日期载体、YEAR/WAL 和原完整业务键；来源 `trade_date`、原始日期及复权因子数值不变。
- 原 `EtfAdjWriteSession` 代表固定 v1；分版会话显式实现 `Versioned`。适配器核对冻结定义与会话版本，版本不符时在日历、来源和物理预检前停止。
- `EtfAdjSyncJobOwner.definition(2)` 生成独立 v2 定义和请求身份。原 `DEFINITION`、默认构造及默认注册仍是 v1，不改写已有请求、回执或检查点。

控制服务已接通显式 v2 装配：新计划和新执行使用选定布局；恢复、已完成来源再验证及原日志核对使用原账本的作业版本。默认 Spring 构造、作业注册和新计划仍是 v1，尚未增加生产配置开关。默认读取注册、源组作业及调度切换还未接通，不能据此声称完整入口已经完成。其余五张表端口、正式表、MV 和消费者也没有迁移。

## 怎么核验

离线回归核对版本不符先失败、原 v1 默认与编码不变、新布局列名、完整键回读、日期精度、WAL 和目标身份检查。新布局遇到旧物理列或新物理身份时，不能借 Sender 自动补列或继续发送。

实库验收使用已有正式表的两行只读样本，先耐久保存期望、DDL 意图、目标身份和 v2 请求，再写唯一的 `java_d015_etf_adj_layout2_*` 表。每次发送后核对完整键值、类型化读取、行数、WAL 与稳定身份；第一次全部通过后才做第二次幂等写入。客户端停止后，只清理本测试创建且身份未变的表。

```sh
APP_LOCAL_CONFIG=file:/绝对路径/config/application-local.yml \
D015_LAYOUT_LIVE_ACCEPTANCE=true \
D015_LAYOUT_EVIDENCE_ROOT=var/etf-adj-layout-acceptance \
./gradlew :markets:cn:data:test --tests '*EtfAdjLayoutLiveAcceptanceTest'
```

默认不运行此实库测试。证据目录存在未完成记录时先停止；写入未决不自动重发或删表。报告只写错误类型，不复制账号和异常中的配置。未尝试 DDL 的失败可以重新运行；已尝试建表的失败需先人工核对原表和原件。

实际两行验收已通过，隔离表已清理，正式表身份与事务版本在验收期间不变。它验证 Java 读写布局，不证明来源完整、全历史、模型批准或正式迁移已完成。结果见[实库原件](../operations/cn-time-migration/ETF复权v2端口实库验收.json)和[代码验证](../operations/cn-time-migration/ETF复权v2端口代码验证.json)。

## 控制服务怎样保留原版本

`EtfAdjJobService` 的显式构造参数只用于新计划。原有 `--resume-from` 分支直接恢复账本，不重新规划今天的范围或检查点；通过账本 `jobVersion` 选择固定的 canonical 定义，再校验原 JSON、请求指纹和目标身份。当前默认换成另一版也不改写原请求。新运行则必须匹配当前显式选择，不能拿旧计划冒充新版新运行。

目标的 `Versioned` 能力按请求版本创建会话和读取范围。旧目标接口仍固定 v1；返回会话的声明版本也要再核对，不能由旧包装器偷偷返回 v2 会话。原物理身份变了就停止，不能因为逻辑表名相同而改绑。

检查点只合并同一版本、同一目标的原完整回执。即使人为使用相同目标身份，v2 也不能拿 v1 回执拼接连续前缀。原 `IN_DOUBT` 状态仍禁止直接恢复；原日志核对仍先确认写入进程停止，并要求原区间锁、原来源和原写后证明，未满足时不写数据、不释放锁。

这些变化用临时 SQLite 和原冻结 JSON 验证，包括两种配置方向的旧版本恢复、缺失原锁及连续区间跨版本混用。没有执行真实恢复、变更生产配置或清理未决记录，范围见[控制服务验证](../operations/cn-time-migration/ETF复权v2控制服务验证.json)。
