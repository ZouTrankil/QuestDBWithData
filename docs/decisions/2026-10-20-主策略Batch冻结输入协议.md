# 主策略 Batch 冻结输入协议

新请求使用定义 v4，协议进入请求指纹和 `plan.json`。旧 v3 继续按原算法和原计划编码恢复，不因当前默认版本改变而升级。

目标协议维护在根 `config/apps/cn-main-strategy.yml` 的 `app.sync.batch.input-schema`，默认 `v1`，只支持 `v1/v2`。来源采集前可固定目标协议；实际评分仍须读取完整批准清单、证据和训练文件，并核对清单版本与冻结协议一致。配置不能替代来源完整性或批准材料。

`MainStrategyDailyWork` 保留原 `DEFINITION_VERSION=3`，新增 v4 常量及按原版本计算指纹的入口。实际流水线为新任务选择 v4，协调器恢复旧请求时显式使用原版本；Quartz 作业类、任务名和调度暂停状态不变。

v4 指纹绑定原配置指纹、版本域及完整输入协议名。新计划保存 `inputSchema`；协议缺失、改动或与当前冻结配置不符时阻止恢复，不覆盖原文件。评分完成证书还须匹配原计划的协议；缺原计划不能自动重建完成证据。

v3 指纹的原字节不变，旧六字段计划序列化不增加 null 字段。固定样本由 `a26c4cba` 的原方法独立执行得到；新版按 v3 计算时与该向量一致。测试还实际保存和读取临时 SQLite 请求，确认旧 BLOCKED 请求保留原定义、指纹及实例身份。

CLI/Web 也要求批准清单与当前选择的协议一致。已有任务、旧凭证、未决状态和锁不自动升级或清理；更改配置不会把已完成日期当作新任务重做。本轮没有执行生产采集、评分、物理迁移或数据删除。

相关验证包括主策略、Batch、配置加载、架构/模块边界及两个受影响发行包。编译或临时样本通过不代表生产批准、训练、历史证据或完整数值参考已经齐备。
