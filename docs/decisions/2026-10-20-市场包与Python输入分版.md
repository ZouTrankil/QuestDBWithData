# 市场包与 Python 输入分版

新版评分不能配旧字段市场包。市场包版本跟随已核验的评分运行；日期、身份、组件列、时间元数据和目录记录共同分版，不按某列是否存在来猜版本。

v2 日历使用 `calendar_date/previous_trade_date`，ETF 日线使用 `trade_date/instrument_code`，市场状态另外保留 `available_at`。日期必须是 `LocalDate` 或完整 ISO 日期，不把时间戳截成日期。原 v1 继续按原布局读取、重试和查历史；旧文件与回执不覆盖。

`PointInTimeHistory` 的 v2 市场状态带出原证据的 `availableAt`。计算 `updated_at` 仍保留原值，不能替代历史可见时间。v1 输出保持原字段；v2 市场包缺真实可用时刻就停止。

`NativeMarketInputPackagePublisher` 的 Parquet、manifest、组件 schema、来源证明及 SQLite 目录使用同一版本。读取时再次检查目录、评分绑定和不可变字节；同一运行重试仍返回原 manifest，不产生新的正式身份。

Python 的 `JavaDatasetSnapshotClient` 与 `JavaEtfOnlyTop2ScoreInputPublisher` 已按明确版本读取。实际产物保持标准字段，`java_input_schema.model_frame` 在研究模型边界适配旧特征名，不改日期、比例尺度和评分值。版本不一致、身份列混用、不完整业务日期和未知版本均拒绝；不会调用 Python 正式重算或 QuestDB 写入。

隔离验证使用 Java 单元输入，由真实发布器生成 Parquet/JSON/SQLite，再由实际 Python 客户端读取。核对两行行情与评分、可用时刻和更新时间分离、消费前后文件字节不变。测试原件不是生产来源证明；缺实际批准方案、训练文件及历史独立参考，不能据此启用正式发布。

正式应用的 v2 发布保护暂留。下一步仍要接通 Java 正式计划读取和端到端入口，核对生产证据后再切换，不能把单独发布器通过当作整项任务完成。
