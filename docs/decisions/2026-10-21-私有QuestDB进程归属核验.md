# 私有 QuestDB 进程归属核验

## 要解决什么问题

散户情绪 MV 的创建和 FULL 验收原先只接 Windows 进程核验，本机 macOS 无法运行。不能为通过验收而 mock 核验器、只看端口或绕过 fixture。

## 保留哪些限制

私有目录必须位于当前工作目录的 `var/` 内，解析真实路径后检查。D095 固定 `var/d095-isolated-questdb` 和 `18812/19000`；D098 固定 `var/d098-isolated-questdb` 和 `18822/19010`。配置和真实监听都须绑定 `127.0.0.1`；D098 的 marker 必须明确指向当前来源与 MV。

Windows 保留原 PowerShell/CIM 核验。macOS 增加原生探针，未知平台继续拒绝；没有新增跳过检查的配置。

## macOS 怎么核验

- 用固定 `/usr/sbin/lsof` 查询两个 LISTEN 端口，10 秒、32 KiB 上限；两端口必须同属唯一 PID。通配地址、IPv6、重复记录、未知输出、缺失监听均拒绝。
- 用 `ProcessHandle` 取真实可执行文件、原始参数与启动时刻。要求 Java 进程，明确的 `io.questdb.ServerMain` 或 `io.questdb/io.questdb.ServerMain` 入口，以及唯一的绝对 `-d` 目录。目录可经符号链接指向同一真实路径，不能按当前 JVM 的 cwd 猜另一进程的相对路径。
- 按 JVM 参数位置识别主类；业务参数中夹带同名字符串不算入口。未知选项、argfile 和未核定的 jar manifest 不猜测放行。
- 连续两次观察一致后才接受，并在同一会话中固定 PID、启动时刻、可执行文件和完整参数。进程退出、重启、PID 复用或参数变化均拒绝；中断时终止系统查询并保留线程中断状态。

历史请求仍按原物理目标恢复，进程探针不代替完整来源、业务键值、WAL、MV 定义和检查点核验。新会话可重新核验重启后的同一物理实例，不能借此重新认领换代的表。

## 本轮验证范围

覆盖原 Windows 分支和 macOS 的目录、fixture、歧义监听、伪主类、重复目录、进程换代、超时和中断。真实本机普通 Java 监听器应被拒绝；独立同版 QuestDB 私有实例用于验证实际进程归属，未在这一批创建业务表或执行 MV 刷新。结果与剩余范围见[验证记录](../operations/cn-time-migration/macOS私有实例进程核验.json)。

独立 JDK 和 QuestDB 只放在任务的 `var/` 工具目录，下载摘要须与官方 release 资产一致，不改系统默认 JDK。生产应用仍按项目原 JDK 构建；私有服务器运行时单独指定。
