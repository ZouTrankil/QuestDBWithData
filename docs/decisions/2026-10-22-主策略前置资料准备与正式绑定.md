# 主策略前置资料准备与正式绑定

主策略启动补跑前，先通过原owner准备交易日历、股票资料和ETF目录。停牌与ETF目录在`main-strategy`配置中明确绑定同名正式表；`data`有限CLI继续保留隔离默认及环境覆盖方式。

## 执行与恢复

协调器持有原作业锁后，先检查是否还有待恢复的主策略实例。有则沿原请求恢复，不刷新其静态输入；没有才调用前置准备，再选取已完成交易日。原v3/v4任务版本、指纹及阶段不改。

三个前置步骤依次执行：

1. 日历：按上海观察日，核对前后各31天的SSE/SZSE完整日历。窗口之外的历史仍需明确补数。
2. 股票资料：使用已有全目录发现和保留历史规则。
3. ETF目录：使用已有全目录来源、旧键保留和完整值回读。

每步在调用原owner前，先耐久保存运行编号、冻结请求和目标身份。owner完成后，再检查其账本状态、原结果和稳定WAL版本，保存编排凭证。相同观察日重启只复用该原运行；意图后异常、目标变化或未决状态均停止，不自动换编号重发。

凭证在原`app.sync.batch.artifact-root/reference-preparation-v1`下。它只记录编排进度，不代替同步账本、来源覆盖清单或正式DataReady凭证。写入责任、区间锁及发布恢复仍归原owner。

原owner完成明确恢复后，可以用`reconcile-main-strategy-reference --date DATE --table TABLE --writer-stopped true`补齐前置编排凭证。此命令不发送数据，不认证未决运行；它重新核对原日历来源、股票全快照或ETF完整目录及原来源摘要。旧凭证不覆盖，异常保留原意图。

## 部署边界

方案、训练文件、批准摘要、来源覆盖和计划库属于评分及正式计划阶段。它们可以只存在于目标机器，不要求复制到开发工作区。`status`明确标注只反映当前进程配置路径；本机缺文件不能推出目标机器丢失。

这些改动没有启动正式日批、修改数据库或迁移日期布局。目标机器仍须核对唯一writer、原账本/锁、实际表布局、文件摘要、真实增量和消费者；连接不可达时不能宣称主策略依赖已验收。
