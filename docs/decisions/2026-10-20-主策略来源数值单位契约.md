# 主策略来源数值单位契约

数值单位进入 `DatasetDefinition.Column.numeric`，目录、CSV 和 v2 主策略证明使用同一份定义。以前只有文字说明，难以区分不同来源的同名 `amount`；ETF 持仓比例的 Java 描述还直接写成百分数，超出了来源说明。

`NumericContract` 是纯 JDK 值对象，记录来源单位、基准单位、倍率、币种、分母、价格口径、缺失规则和依据。倍率仅描述单位关系，不修改读取、写入或模型数值。只有数值存储列能带此契约；未知比例尺度必须标 `UNVERIFIED` 且倍率为 null，不能暗取 `1` 或 `0.01`。

本批接入 `daily`、`daily_basic`、`etf_daily`、`etf_portfolio` 四项来源契约。来源说明于 2026-10-20 重新核对：

| 来源 | 主要约定 |
| --- | --- |
| [股票日线](https://tushare.pro/document/2?doc_id=27) | 成交金额千元、成交量手；涨跌幅是百分数，基准为来源除权昨收；原始成交价与该昨收价不能混用 |
| [每日指标](https://tushare.pro/document/2?doc_id=32) | 市值万元、股本万股；普通和自由流通换手率分母不同；市盈率、市净率等保留倍数 |
| [ETF 日线](https://tushare.pro/document/2?doc_id=127) | 金额千元、量为手、价格元、涨跌幅百分数；不从相似列名推断其昨收除权规则 |
| [基金持仓](https://tushare.pro/document/2?doc_id=121) | `amount` 是股数，`mkv` 是元；两个比例字段的精确分母及百分数/小数尺度待原报告核验，当前不换算 |

“手”仍以手作为基准单位，没有在契约中统一乘 100。null 与真实零值保持区别；数值阈值、评分公式及训练列名不变。币种说明限于当前 CN 契约范围，不能套到其他市场。

旧 `JobDefinitionJson` 用 mixin 排除新增的 `Column.numeric`，旧 Dataset JSON 的字段集合保持不变；单位元数据单独从目录 DTO 和 v2 的 `numericFieldContracts` 发布。它不是旧恢复协议的隐式升级。旧数据集版本、Job 版本、请求身份、物理列、键、DDL 和行编码不因此改变。两项旧 L2 Dataset golden 与专门的编码对照检查旧编码，不重写保留原件。

v2 证明的这部分带 `schemaVersion=1`，明确 `valuesConverted=false`、`unitContractsComplete=false`、`modelAcceptanceVerified=false`。它记录来源字段契约，不宣称四项都是评分行的直接投影，也不宣称 JOIN、L2、全部因子、MV 和生产材料已完成单位验收。旧 v1 证明不增加此部分。

字段说明生成器继续从 `collected-fields.json` 维护的官方原文导出来源单位；新契约补充本地数值解释，不把待核的比例尺度写成官方已确认结论。完整单位矩阵、相关上游、生产原件、独立数值参考和正式迁移仍需完成。
