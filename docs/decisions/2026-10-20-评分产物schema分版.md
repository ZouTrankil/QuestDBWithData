# 评分产物 schema 分版

评分 Parquet 与目录必须知道自己是哪版。只改 `ts_code` 列名、不改目录或读取协议，会让历史运行被新消费者误读。

`ScoreArtifactPublisher` 从不可变来源证明选择版本。旧证明没有 `inputSchema`，按 v1 读取；v2 必须同时声明标准输入、覆盖协议和键编码。v1 面板只接收 `ts_code`，v2 只接收 `instrument_code`，混用或身份键重复直接拒绝。

实际文件、来源证明和 SQLite 回执保持原子发布规则。目录的 `schema_version` 分别记录 v1/v2，`producer_version` 仍表示实现版本，不用它冒充数据 schema。已有文件的目录登记不能覆盖角色、schema、生产者或运行身份。

读取 `latest`、`byRun` 与历史日期时，评分与覆盖两项必须声明同一已知 schema，且与证明文件一致。返回值携带输入版本，旧构造入口默认 v1。旧周计划继续绑定原运行，没有改写旧文件或原回执。

测试在临时目录实际写读 Parquet/SQLite，核对标准身份、DATE、评分数值和布尔值；验证旧运行仍能读取、错误证明不推进别名，以及同时篡改两项目录版本仍会失败。测试证明协议行为，不代表正式生产材料已验收。

此批只接通评分发布器。正式应用仍因市场输入包、计划与 Python 消费端未贯通而阻止 v2 发布；没有执行正式评分、数据库迁移或别名切换。
