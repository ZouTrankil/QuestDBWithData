# 美股基础行情使用独立有限入口

`markets/us` 保留美国模型、来源解释和目录说明，`markets/us/data-app` 装配行情采集与 QuestDB 写入，不加载 A 股应用。公共 `platform/engine/questdb` 提供有界写入适配器，继续使用原 `SyncRunLedger`、`SyncJobRunner`、完整键值回读和未决锁协议。

日线保存交易日，分钟保存真实 UTC 起点；来源与频率进入业务键。未复权价、调整价、现金分红和拆股因子分列，IEX 场所量独立说明。原始来源及规范化输入先冻结，未完成 WAL 和回读不推进检查点。

公开配置只放根 `config/`，新入口加入 profile、资源分发、Gradle 聚合、锁文件和模块边界检查。账户凭据仅在本机覆盖中保存。

BTC 的纯映射和字段在 `markets/btc`，独立入口在 `markets/btc/data-app`。两个市场复用通用预算、冻结响应、QWP 和验收端口，不互调业务实现。Binance 历史现货从 2025 年起使用微秒，合约仍为毫秒；日线合成前必须有完整的 UTC 24 小时。官方停市造成缺失时不合成价格：只有原归档、精确小时 REST 空记录和官方事实齐备，且原生日线与实际小时 OHLCV 一致，才单独登记缺口并发布原生日线。

INT 和纳秒时间使用 QWP 原生类型，不能经过 HTTP ILP 静默降级。ITCH 原始无符号订单编号保存为十进制字符串，价格保存四位定点原整数，缺少的执行价格不补造。

当前 Nasdaq Trader 挂牌快照和供应商历史证券表是不同范围。公开源可用性、退市、OTC 和历史指数成分需分别列出缺口，不能以当前股票成功子集代替全市场历史。完整范围和剩余验收见[美股与跨资产基础行情](../us-market-data.md)。ITCH 部分文件也不能标成完整交易日。

历史目录按来源原始行号保存同代码的不同窗口，不能按证券代码和场所去重。FRED 指数沿用既有六列正式表，先冻结旧行，再只补已证实缺失的业务键；发送前再次检查，补后逐字段证明旧值未变。来源缺值和历史修订不覆盖旧值。

全市场日线把少量证券的完整原文和清单一起冻结为 ZIP，再按日期排序发布；保持原字段、来源摘要和业务键，降低逐证券跨年回填造成的写放大。组与成员原子推进检查点，未决组保留并阻止重发；原运行成功后的队列补验另走显式命令。

供应商分钟原文存在休市日零量平价补齐记录，因此保留原表并增加正常交易时段只读视图。日历使用带官方原文摘要的年度资源，安装时比对原文事实；按纽约时区及半日市时间过滤，原有价格不改写。日历版本进入视图列，未核对的年份不猜测。

当前官方证券名称与供应商历史 Stock 标签冲突时保留待复核状态；不把当前 Right、优先股等直接作为普通股票发布，也不按当前类别删除可能存在的历史普通股票窗口。已经发送或验收的运行保持原状态，原文和原来源失败证据保留。

官方明确标记为 ETF 的当前代码也适用这条边界。供应商的 Stock 标签不能证明旧股票与当前基金是同一证券；未发布任务进入独立的 ETF 历史复核原因，全部旧窗口保留。已经绑定来源组或验收的任务不改写，六只参照 ETF 的已验收来源不受影响。只读身份报告按原目录行展示类别和窗口冲突，不按代码存在价格自动合并证券或宣布历史完成。

全市场日线可显式冻结较大的发送页，最多一万行和 8 MiB；HTTP 回读仍按原上限分段，完整键值及 WAL 验证不变。该布局使用版本 2 请求参数，不改变表结构、业务键或来源配额；旧请求与其他入口保留五千行、4 MiB。恢复时同时校验原 prepared 和请求中的分页，不能用当前配置解释旧切片。

挂牌进程在原队列锁内启动单一来源预取线程，只对 `PLANNED` 做有界下载和原子条件更新。消费侧仅发布已冻结的 `FETCHED`，等待足够成员后成组，末组仍完整发布；正式发布锁、账本和恢复协议保持原样。预取使用独立 SQLite 连接和同一持久请求预算，不占用正式写入线程，也不在网络调用期间持有队列事务。缓存最多 500 个响应，异常和停止信号会关闭线程，不能另起未决写入或覆盖来源复核。

HCSG、HCTI 的一次 I/O 错误曾直接结束来源任务，核对原状态后重试却取得了有效原文。因此预取增加持久、有上限的来源重试：I/O 错误及 HTTP 5xx 默认最多三次，失败后等待五秒、十秒，并遵守更晚的 `Retry-After`。任务 ID、截止日、原预算和正式发布流程不变；SQLite 单独保留每次失败及原 proof，状态和历史原子提交。等待中的任务跳过，其他来源可继续；重启仍按已有失败次数和等待时刻执行，下调上限不会多发请求。429、配额等待和取消不算临时错误次数，4xx、响应超限和已冻结坏数据不自动重试。旧失败和已有冻结痕迹须先核对，不自动恢复；只适用于预取路径。

日线按年度发布更多来源，减少反复跨年合并：版本 2 ZIP 最多 128 个响应、64 MiB，并冻结完整连续窗口、原发送页及逐年行数。每次正式运行仍最多十万行，逐字段和 WAL 验证不放宽。空窗口只是完整原文中确实没有行，不能补造价格。

同一组的发送、恢复和结束复核原来都会重新解析各证券二十年 JSON。现在解析时保留本组私有报价数组、纽约日期和完整公司行动，后续年度投影重用这些不可变输入；每次重新生成行对象，不缓存发送结果或实库行。对外来源列表、七字段解析结果、版本 2 清单、任务身份、年度边界和预算保持原样；原 ZIP 摘要变化仍阻止发送，已有成功段仍逐字段重验。缓存随组释放，不使用全局缓存。

新窗口表与组、成员在同一事务中建立；先提交每段发送意图，再交给原正式写入方。只有 `PLANNED` 可自动继续；`PUBLISHING` 必须显式核对原运行。重启先重验成功段，结束前再次沿全部原运行核对完整数据和物理对象，随后统一推进成员。允许在已验收段间停止，不清除未决状态；旧组、旧 ID 和旧恢复入口保持原样。

同一市场代码也可能被不同发行人先后使用，供应商再按当前代码回填旧价格，会产生窗口重叠。实测 Tiingo 搜索为两个 AMTD 返回不同永久代码，永久代码元数据请求虽为 404，价格请求仍可成功。不能用当前 AMTD 的价格覆盖旧 TD Ameritrade，也不能把搜索命中当作历史价格已取得。

保持原日线表二十列及业务键；旧证券以实际请求的永久代码隔离，原市场代码和当前已经验收的价格不改写。新增 `us_security_identifiers` 保存经过复核的映射，键为取得时间、供应商及永久证券代码。价格先独立验收，再登记映射；映射导入须核对搜索原文中的唯一身份、原目录行、原价格运行成功状态、冻结摘要、物理对象及全部字段。不同永久证券不能借同一价格代码覆盖重叠窗口，未决运行或部分价格不能生成映射。

供应商可用截止日不等于最后交易日。TD Ameritrade 的 Nasdaq 公告最后交易日为 2020-10-05，供应商 6–7 日零量平价保留在探针原文中，不计入该证券的交易历史。永久代码映射是有限来源证据，不代表其他同代码窗口或全市场身份已完成。

ATTT 的真实搜索原文有唯一永久代码和证券名称，但 FIGI 为 JSON null。FIGI 不是供应商永久代码本身，不能为了入库补造标识，也不能因此丢弃已核实价格的永久映射。数据定义升级为版本 2，只有该列可空；清单版本 1 保持原必填校验，版本 2 接受明确的 JSON null。字段必须存在，来源缺字段、数值、空串和文本 `"null"` 不能冒充明确空值；其余身份、目录、完整价格和旧快照保护不变。实际十八列、表和键不变，旧六条非空映射保留原值与来源证据。
