# Batch 独立来源日期布局

Batch 的 `source_*` 使用独立来源契约。正式 `data.*` 的 v2 配置不会自动切换它，旧请求也不能随当前配置改绑。

五个来源新增显式写入定义：`etf_adj-trade-date-v2`、`etf_daily-trade-date-v2`、`etf_share-trade-date-v2`、`stk_st_daily-trade-date-v2`、`stk_suspend-trade-date-v2`。它们将目标指定列从 `timestamp` 改为 `trade_date`。类型、精度、列顺序、分区、业务键含义、单位和日期值保持原样；ETF 日线仍为 `TIMESTAMP_NS`。

采集合同和不可变来源归档仍用 v1。执行器先按原合同核验日期、覆盖、业务键和质量，再按请求的定义版本映射物理列。定义版本参与原有实例身份，因此新旧布局得到不同隔离目标。旧归档、请求、ILP 和批次身份不重写，未决批次继续走原恢复协议。

手工启动和冻结盘后计划都能选择新定义。DataReady 要求凭证匹配原计划的定义、修订、证券范围和日历；另一布局的最新凭证不能代替它。缺原计划时停止，不猜测默认版本。

实际回归发现 `is_st=1` 经 JSON 回读可能从 Long 变为 Integer。质量检查改为按数值判定；来源合同仍负责整数类型和范围核验。

本次不切正式默认，不迁正式表，也不让 Batch 接管正式写入。`l2_archive_integrity` 写的是独立归档产品，不属于这五项来源；L2 日特征继续按原正式来源和显式布局处理。
