# BTC 研究批次与日更

六组正式表继续由 Java 写 QuestDB，Python 只读并发布研究文件。旧表、单表导出、请求及恢复账本不迁移。

## 研究批次

新增批次清单 v1、质量规则 v2。`objects/` 保存不可变 Parquet，`batches/<id>/` 保存清单与质量报告；ID 是清单内容摘要，只有 `current.json` 可原子替换。初版质量规则 v1 的固定批次继续可读。

发布前后检查全部成员的物理对象和 WAL，回读 Parquet 全字段，再针对固定文件生成质量报告。质量 v2 绑定成员摘要、UTC 左闭右开范围、规则、字段问题和共同完整小时价格区间。正式认证逐行匹配原成功 prepared、回执、账本成功状态和当前物理目标；恢复成功的运行额外核验原恢复意图与成功回执。

`dataVerified` 只认证已导出的实际记录，不认证缺失事件、完整时间轴或历史 PIT。缺原账本可以导出未认证候选，严格读取默认拒绝。字段冲突不自动排除其他字段，探索模式不静默删除原行。

日更在候选发布前检查来源末端日期及正式证明；延迟、未决或修订待核对时保留旧指针。历史质量缺口可带报告发布，不能伪装成齐全。

## 增量与修订

完整月仍优先月包。仅未发送月包的官方 HTTP 404 允许按原日任务补日包，校验失败不走回退。资金费率以原 API 区间并集找缺日期，冻结过或未决的任务不改范围。月包与 API 重叠继续走原值核对，API 成功引用单独保留，月包缺失仍可有界重试。

日更默认检查最近两个完整月，每周再查一个旧月，上限十八个文件。旧月游标只记录探测进度，只有完整探测成功才前进；旧历史轮查不是每日全历史检查。发现修订不自动改价，改键和删除继续待明确迁移。

## 恢复与运行

冻结资金费率 API 可从原响应重算全部字段，核对原任务后恢复原运行；不重新取远端响应。同键修订组成功恢复时同步收拢附属修订记录。底层部分发送恢复仍受原首切片和一万行上限约束，旧新值冲突不自动重发。

日更编排使用单进程锁，调用原 Java writer 和预算。当前部署是用户级 macOS 定时入口，登录、休眠和时区改变的限制见[部署说明](../../deploy/btc-data/README.md)。配置全部在根 `config/apps/btc-data.yml`。

备份取得原采集、发布和研究锁，SQLite 使用 backup API，逐文件摘要和引用在隔离副本核对。原绝对路径不重写，副本只读，不能直接启动第二个 writer。灾难切换仍需原物理表与单 writer 归属验收。
