# 公告与利率逻辑日期读取

两项异动表的物理列叫 `trade_date`，来源说明却是公告日；三项利率表使用 `timestamp/date`，不是证券交易日。过去只有原表投影，读取者容易按列名猜错日期角色；通用存储列校验还不能表达 `1w/1m` 这些既有利率列。

`StockShockDatasets` 和 `InterestRateDatasets` 增加五项只读 v2 契约，接入实际 DatasetRegistry 和通用读取绑定。公告用 `announcement_date`，利率用 `observation_date`；物理列、日期载体、数值及去重键保留。公告键仍包含证券、公告日期、reason 和 period；period 保留原文，不猜区间或可用时刻。trade_market 也保留市场/板块原文，不强行当标准交易所代码。

业务日期返回 `LocalDate`，不加八小时、不按 SSE 日历补利率行，也不把日期当作真实可用时刻。利率期限使用明确逻辑名，原值不缩放；单位尺度仍需来源证据单独验收。

core 只对物理列允许受限的数字开头标识，表名和逻辑名保持原校验。实际 SQL 始终引用物理列，不能拼入引号、空白或表达式。该变化不增加客户端、框架或市场特有类型。

目录详情的 name 仍是物理名，新增 sourceName/logicalName，来源字典不覆盖实际契约。逐字段 CSV 复用相同详情，未知映射留空并标待核。原对象清单导出格式不变。

有限命令 `inspect-cn-reference-dates` 经实际通用读取器检查五项：上海当前日期向前一年到明日的左闭右开窗口，每表返回两行，底层最多额外读一行判断下一页。只执行读取，不启动 owner、不建表或刷新 MV，不签发来源完整性证书。报告记录物理身份；有 stage 字样的活动目录不能据名字删除。

实库五项均取得样本，日期解码与数字期限列查询通过。它不证明历史全量、单位尺度、来源覆盖、WAL 完整性或原 writer 已停止。新契约不接管写入，旧来源合同及生成的物理投影保持原布局；正式改列和恢复切换仍未执行。

严重异动样本还出现 `announcement_date=2026-02-25`、`period=2026022520260311`。仅凭 period 原文不能断定历史字段值是否正确，更不能推导精确可用时刻；仍需原响应核对。本批按已核对来源字段约定建立逻辑映射，没有改这些值，也没有把它们验收为历史时点输入。
