# CN 模型按数据类别归组

共享模型原来平铺在 domain、table 和 policy 下，不容易从来源条目定位。现在参考 Tushare 的数据分类，把 229 个现有模型归入股票、基金、指数、期货、现货、债券、外汇、宏观等目录；本地衍生计算、L2 和跨类别规则单列。股票继续分基础、行情、财务、参考、特色、两融、资金流和概念。

每个类别下放对应业务模型、业务键和 Dataset 契约。生成的存储投影仍以 table/view/materializedview 区分对象类型，不把同名业务模型与存储投影混为一类。基金目录合并当前 ETF 与公募条目，不为尚未接入的官网栏目创建空目录。

来源字段资料保存 category 与 modelPackage，生成器和导出共用这份映射。分类必须是合法的显式 Java 子包，不按表名前缀推断市场。旧 catalog 生成 CN 来源模型时以维护资料的分类为准，避免再次平铺；其他模型可在 catalog 中指定 category。

同步更新引用和反射加载位置；不改变表名、字段、时间、业务键、数据版本、来源、任务身份、Quartz 类名和恢复协议。旧 outputs 保留原导出快照，新的分类导出另建目录。

验证：全部模块主代码和测试代码编译通过；23 个生成器用例、180 个相关离线用例通过，覆盖模型契约、读取绑定、映射、L2 固定样本与 owner 规则。229 个模型除包声明、导入和类型限定名外保持一致，CN jar 已无旧包 class。模块边界、依赖兼容、Batch 驱动隔离与根/CN 数据/主策略/实时 L2 发行包构建通过。分类导出包含 70 个模型、1360 个字段。

`architectureTest` 仍被已有的根架构测试源码缺失拦截；没有绕过检查，也没有执行真实来源或数据库写入验收。读取绑定测试保留原始类型清单，只在断言中明确对应新的模型包名。
