# BTC 缺日补齐与来源核对

历史月包有缺项时，要继续核对日包和官方 API，不能把月包缺项直接认定为交易所没有数据。本次在日包和 API 找到 528 根可补齐价格，正式补写暂被数据库连接故障阻断。

## 核对与正式写入分开

`tools/btc_quality_review.py` 从固定研究批次生成计划。计划绑定批次 ID、质量报告 SHA-256、问题 ID、数据集和 UTC 日期，每轮最多 64 个日期请求。

Java 的 `audit-binance-quality` 复用原 `BinanceArchiveSource`、持久请求预算、不可变原文目录和归档锁。月包优先复用已校验的冻结版本，日包逐项校验官方 CHECKSUM，REST 保存原 JSON。REST 只做字段投影，毫秒精度不补成微秒精度；不会将投影 ZIP 当作官方原件。核对没有正式写入意图，不推进正式检查点，也不宣称历史 PIT。

四个现货冲突日另取官方分钟日包。只在 1,440 根 UTC 分钟网格、结束边界和字段有效时计算日汇总；使用 Decimal 累加成交字段，成交笔数精确比较。分钟证据支持某侧仍不自动覆盖另一侧。

现货缺口继续沿同一核对入口获取分钟和聚合成交日包。计划可显式启用 `aggregateTradesCheck`，仅允许现货小时请求；原 ZIP、CHECKSUM 和报告继续保存到原目录。下载不生成正式 K 线，也不修改原发布队列。

首笔资金费率依赖起始日之前的价格。来源核对新增显式 `fundingBoundaryDependency`，仅放行 `2019-12-31` 四类小时价格原件；正式同步仍从 2020 年开始，后续研究关联接入另行验收。

聚合成交包大于普通 K 线包，单响应上限为 64 MiB。根配置 `quality-trade-download-timeout-seconds` 默认 180 秒、最多 300 秒，只用于此类大包。公共 HTTP 读取新增显式有界时限参数，旧调用保持 60 秒；请求预算、失败记账和不可变原文协议保持原规则。真实下载中断保留失败报告，再以有限计划重试。

## 本轮只补完整缺日

`repair-binance-quality` 只处理标记价、指数价的完整缺日。Python 要求原固定批次当天没有记录，日包和 REST 各有完整 24 个小时键、业务值一致。Java 再核对日包摘要和完整性，随后交给原 `BinanceArchiveSync`。

补齐仍用原任务身份、队列、物理目标、正式写入与恢复协议。显式来源重试也必须绑定原核对摘要；新下载版本不同就停止。已核验任务跳过，正式未决不重发、不解锁。现货已有值修订、部分小时缺失、分钟重建产物都不借此入口自动写入。

Java 正常退出后，Python 还要逐项确认原队列为 `VERIFIED`，再执行全量来源证据认证和研究批次发布。修复保持原批次截止日，不计作新一天的日更观察。

## 连接失败与来源失败分开

正式写入前的目标核对失败记作 `BLOCKED_TARGET`；下载或来源解析失败仍是 `SKIPPED_SOURCE`。`BLOCKED_TARGET` 没有正式 run，可在后续同步中复用原文重新核对目标；`PUBLISHING` 仍只走原运行恢复。旧状态和旧日志不回写。

研究查询异常保存阶段、表、查询指纹、超时值、耗时、异常类型和调用位置，不复制完整 SQL、连接地址或凭据。缺日修复的每次尝试另存原根目录下的记录，失败不写成功回执、不切换研究指针。
