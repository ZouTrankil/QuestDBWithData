# Batch 合并到市场入口

根 `batch-app` 不再单独保留。A 股 Job、管理 API、控制 CLI 和 Quartz 装配归 `markets/cn/batch`，由 `markets/cn/data-app` 的常驻进程按配置托管。通用执行、写入和账本继续归 `platform/engine/batch`；core 不引入调度框架或数据库。

## 启动与隔离

`jdb.enabled` 默认关闭。启用后市场入口在同一 JVM 内创建独立 Batch 容器，继承已解析的配置，不共享 QuestDB 数据源、事务管理器和来源 Bean。宿主关闭或启动失败时释放 Batch 资源。有限 CLI 强制不启动，主策略和实时 L2 不导入托管装配。

`jdb.scheduling-enabled` 和已保存的触发器暂停状态继续生效。启用托管不代表任务已经验收，也不自动恢复或重发未决写入。

## 兼容与迁移

保留 Job ID、Quartz 持久类名、账本结构、来源身份、时间规则和恢复协议。原 SQLite、归档和物理目标不迁移，不重建调度记录。先停止旧 Batch 服务，再启用市场托管。

`batchRun` 和旧 `questdb-batch` 脚本改为启动统一 A 股数据应用并启用托管。`batchDistZip` 保留旧文件名，但包含统一市场依赖和数据 API；部署时要同时处理数据 API 端口，不能与另一个数据 API 实例重复启动。`batchControl` 及离线 L2 命令继续保留。

美股和 BTC 没有因此获得新的独立任务或启动应用。美国利率来源继续按现有契约装配，未扩展来源覆盖。

## 验证范围

Batch、入口启动和托管生命周期的离线测试共 2230 项通过；额外的真实 CLI 子进程测试通过，显式开启 Batch 也不创建后台数据库。`architectureTest`、`verifyModuleBoundaries`、`verifyDependencyVersionCompatibility` 和 `verifyBatchDistributionDatabaseDrivers` 通过，统一数据、兼容 Batch、主策略发行包构建通过。公开配置、发行包凭据和文档相对链接检查通过。

本次未启动正式调度，也未执行真实来源、QuestDB 写入或生产账本迁移验收。
