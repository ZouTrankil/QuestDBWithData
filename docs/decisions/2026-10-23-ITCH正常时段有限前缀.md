# ITCH 正常时段有限前缀

首批只取一个正常时段消息片段。日线全市场长尾继续保留原队列，原盘前 ITCH 记录也保留。

## 来源与边界

使用 [Nasdaq 官方目录](https://emi.nasdaq.com/ITCH/Nasdaq%20ITCH/)的 `S061226-v50.txt.gz`。按 [ITCH 5.0 协议](https://www.nasdaqtrader.com/content/technicalsupport/specifications/dataproducts/NQTVITCHSpecification.pdf)从文件开头连续解压，保留当日证券目录、原消息序号和解压字节偏移，不猜压缩重启位置。目标时刻按 `America/New_York` 解释，正式 `ts` 保留 UTC 纳秒。

`fetch-itch-prefix` 只冻结来源，不创建 Native 写入或推进行情检查点。默认从 09:31 开始保留连续 100000 条完整消息；必须落在已核对的正常会话内，并包含成交类消息。每次只请求 8 MiB，压缩前缀上限 1 GiB，扫描上限一亿条消息。达到上限仍未齐备就失败并保留原件，不发布半段。

每次 Range 请求先进入原 `api-budget.sqlite3`，本地预算独立记录 `nasdaq-itch/public`。默认滚动一小时 240 次、24 小时 1000 次、31 天 4 GiB、间隔两秒；首批滚动 31 天只允许一个文件日期，同日分段共用该资源；这只是本地限制，不代表供应商额度。必须返回精确的 HTTP 206 范围、长度和原始编码，后续请求通过强 ETag 或 Last-Modified 的 `If-Range` 固定实体，整文件长度也须相同。忽略 Range 的 200 响应被拒收，未知带宽保留原预留预算。

每段保存原响应、摘要和请求回执；最终保存合并前缀及元数据。`sourceComplete=false` 始终保留。选中消息结束偏移只描述选中片段，不代表已下载前缀中的最后完整消息，也不能当作 gzip 全文件 CRC 通过。

## 配置与正式发布

配置只在根 `config/apps/us-data.yml`，`app.market-data.itch-*` 支持原标准环境覆盖。取数使用独立来源锁和 `us-itch-stop.request`；原日线停止标记保持。停止、来源变化或配额等待都不生成新正式写入。

发行包在仓库根目录运行，实际私密配置仍按原加载方式提供：

```powershell
# 只冻结来源，结果给出 source、metadata、firstMessage 和 messageCount。
.\build\modules\markets\us\data-app\_output\install\us-data\bin\us-data.bat fetch-itch-prefix

# 标准覆盖示例；不能超过配置允许的消息或字节上限。
$env:APP_MARKET_DATA_ITCH_SAMPLE_MESSAGE_COUNT = '1000'
```

正式导入使用取数结果中的实际路径和原序号，不猜边界：

```powershell
.\build\modules\markets\us\data-app\_output\install\us-data\bin\us-data.bat import-itch `
  --source '<source>' --metadata '<metadata>' `
  --first-message '<firstMessage>' --message-count '<messageCount>' `
  --maximum-first-message 100000000
```

独立解码核对来源后，显式使用原 `import-itch` 发布选中片段。旧命令默认首消息上限仍为五百万；正常时段可通过 `--maximum-first-message` 提高，但不能超过根配置的扫描上限。输入改为流式读取，不把整个压缩前缀载入内存。原表、十六列、业务键 `ts,source_sha256,message_index`、单写入者及未决恢复协议不变。

公共发布器的九处原件摘要检查也改为流式 SHA-256；检查时机、字节摘要、prepared 和恢复归属都保持原规则。这个改动只减少大原件在堆中的副本，不缩减正式校验。

前缀变长会改变 `source_sha256`。本轮只选与原盘前范围不重叠的序号，读取须固定来源和区间；以后不能把不同前缀下的相同原消息重复计为成交，也不能把两个离散区间宣称为连续全日。

正式验收须核对原二进制、prepared、HTTP 和 PGWire 的全部十六列，时间使用整数纳秒；再检查原物理对象、稳定 WAL、Native 状态和旧范围。出现未决写入时按原运行恢复，不重发或换 UUID。

这个片段可用于研究部分订单消息，但不代表完整订单簿、全日成交或全市场覆盖。执行消息的价格可能依赖片段以前的原订单；不能用空价格补值计算 VWAP，也不能把非显示成交消息的固定方向字段当成主动买卖方向。

`observed_at` 保留本次实际取数时刻，不代表文件交易日当时已经取得这份历史样本。
