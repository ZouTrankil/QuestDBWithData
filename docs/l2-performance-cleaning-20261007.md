# Level2 Java 性能与 09/28–09/30 清洗准备

测量日期：2026-10-07。数据日期：2026-09-28、09-29、09-30。

## 执行结论

建议使用 **Java 24、4 个 worker、`-Xms1g -Xmx24g`** 启动三日日特征清洗。
CSV 解析中的重复正则与日期解析已优化；同一组真实数据，单线程耗时降低 **38.7%**，
线程累计分配量降低约 **80.6%**。增加到 8 个 worker 相对 4 个仅缩短约 **8.7%**。

实际批处理入口已经处理三天共 **45 个标的日、2.883 GB CSV**，包含股票、ETF、大小文件分位样本，
以及归档最大文件中的债券/回购压力样本。三天分别成功 15 条，失败 0，首跑 **73.3 秒**。
首跑包含输入 SHA256 双重读取、P0–P13 计算、单标的原子落盘、检查点和每日 JSONL 汇总。
峰值堆 **14.1 GiB**，进程 RSS **16.3 GiB**；进程 CPU 332.0 秒，GC 暂停累计 6.45 秒。

同一输入的断点续跑为 **3.1 秒**，正式入口复用 **45/45** 个检查点、重新计算 **0**，三日汇总 SHA256 均未变化。
09/28 的 15 条完整 JSON 与优化前单线程基准逐标的字节一致。正式 PowerShell → Gradle → Java 入口也已执行通过；
其约 32.5 秒包含隔离构建与 Gradle/JVM 启动，不能与纯 Java 续跑计时混用。

当前完成的是抽样计算和全量清洗准备；三日归档尚未全量解压、全量计算或写入正式数据库。
产物是既有 `l2_daily_features` 模型的 110 字段 JSONL，版本为 `v1.3` / `dfcf_csv_v1.2`。

## 并发测量

数据：09/28 固定 15 个标的、937.4 MB CSV。各配置独立 JVM，同样 24 GiB 堆，
预热 1 轮、正式测量 2 轮。时间为两轮中位数；内存为两轮采样峰值的最大值。
本表包含解析和特征计算，未包含批处理入口的输入哈希及检查点落盘。

| 配置 | 耗时（秒） | 测量范围（秒） | 峰值 RSS（GiB） | 累计分配量中位数（GiB） |
|---|---:|---:|---:|---:|
| 原版，1 worker | 91.0 | 90.5–91.5 | 7.6 | 129.2 |
| 优化后，1 worker | 55.8 | 55.5–56.1 | 6.8 | 25.0 |
| 优化后，2 workers | 30.7 | 30.2–31.2 | 11.2 | 25.1 |
| 优化后，4 workers | 23.2 | 23.0–23.3 | 18.0 | 25.1 |
| 优化后，8 workers | 21.1 | 21.1–21.2 | 18.6 | 25.0 |

优化后解析仍占单线程标的累计处理时间约 76%。本次改动：

- 数值单元格的 infinity 判断使用等价 ASCII 判断，消除逐单元格正则编译。
- 八位自然日直接读取数字，再用 `LocalDate.of` 保留日历校验。
- 成交、委托、快照映射复用逐行已经验证的日期，消除重复解析。

性能输出守卫覆盖 5 种配置、150 次正式标的计算；同一标的日的完整 110 字段 JSON SHA256 相同。
本次没有重跑此前的 Java/Python 全套准确性验收。此前的 09/24 验收记录见
[原生管线抽样验收](l2-native-pipeline-20261007.md)。

## 耗时规划

根据 09/28 的 15 个样本及三日完整文件大小清单，全部归档代码的 **计算阶段**中心外推约 **1.5 小时**。
建议按 **0.5–2.5 小时**的宽范围规划。解压、正式入库和后续验收另计。

这不是全量实测或完成期限。测量使用已经解压的文件，重复测量主要受益于操作系统热缓存；
小文件固定开销与行情字节成本难以区分，大文件尾任务也影响并发收益。
三日 45 样本首跑用于检查实际批处理开销，未把这组并行耗时作为串行拟合数据。
股票/ETF 白名单确定后，应按白名单重新统计工作量；不能直接按标的数量线性放大 73.3 秒。

## 清洗入口

脚本：[tools/run_l2_native_cleaning.ps1](../tools/run_l2_native_cleaning.ps1)。
日期默认为三日、worker 默认为 4、堆默认为 24 GiB，默认续跑开启。

在仓库根目录的 PowerShell 中，先查看实际计划：

```powershell
$env:JAVA_HOME = 'C:\Users\zouqiang\.jdks\jdk-24.0.2'
.\tools\run_l2_native_cleaning.ps1 -PlanOnly
```

**全部归档代码**的执行命令：

```powershell
.\tools\run_l2_native_cleaning.ps1
```

默认原始输出目录 `D:\l2-native-raw`，特征输出目录 `D:\l2-native-features`。
脚本依次解压三日，再调用 Gradle 的 `l2DailyFeatureBatch`。
每次运行使用独立 Gradle 构建目录和项目缓存，参数通过 UTF-8 JSON 文件传递。

**主策略股票/ETF 范围**须提供正式证券白名单；使用 `-SymbolsFile`：

```powershell
.\tools\run_l2_native_cleaning.ps1 -SymbolsFile 'D:\l2-main-strategy-symbols.txt'
```

白名单为 UTF-8，一行一个规范化代码，例如 `000001.SZ`、`510300.SH`、`159915.SZ`、`588000.SH`。
支持空行、`#` 注释、下划线代码。使用规范化交易所后缀，不能直接把上交所 ETF 的原始 `.SZ` 目录名作为白名单。
脚本仍会解压整个归档，Java 按白名单计算；未提供白名单时，计算全部合法代码目录。
当前未生成正式主策略证券白名单。

若原始文件已完整解压，使用 `-SkipExtract`；断点恢复也建议带上该参数，以免重复解压：

```powershell
.\tools\run_l2_native_cleaning.ps1 -SkipExtract
```

## 落盘、续跑与完成检查

Java 入口每次最多保留 worker 数量的标的任务。每个标的校验三张输入文件的大小及 SHA256，
计算后再次验证输入未变化，再原子落盘特征与检查点。
续跑同时核对输入、结果 SHA256、实际计算类字节码及 Java/Jackson 版本；不匹配时重新计算。
单标的失败写入错误清单，其他标的继续处理，最终返回失败状态。

每日日目录下：

- `features/<symbol>.json`：完整单标的日特征。
- `state/<symbol>.json`：含输入和结果指纹的检查点。
- `progress.jsonl` / `errors.jsonl`：进度与错误。
- `manifest.json`：本次范围、成功/空数据/失败/复用计数、汇总文件 SHA256。
- `l2_daily_features.jsonl`：成功标的按规范化代码排序的每日汇总。

完成判定应同时满足：`manifest.status=COMPLETE`、`published=true`、`counts.failed=0`，
并核对选中标的数以及 `selection.requestedNotPresent`。
汇总文件的 SHA256 必须匹配 `aggregateSha256`。
发生失败时旧的完整汇总文件可能仍保留，因此验收须读取本次 manifest。
