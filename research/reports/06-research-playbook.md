# 研究执行手册：每次完成一个可复查的问题

目标是形成自己的数据和研究能力。默认顺序：数据地图 → 财报/宏观/链上具体问题 → 简单基线 → 验证 → 必要时才用复杂模型。Fiapp 作为日常观察与产品参考，不进入正式信号链。

## 每次研究的最小记录

| 项目 | 必须写什么 | 本包例子 |
| --- | --- | --- |
| 问题 | 一个可以被反证的判断 | 200 日趋势是否减少 BTC 回撤 |
| 对象 | 市场、证券、产品、频率、币种 | Binance BTCUSDT 现货日线、USDT |
| 时间 | 观察、可用、执行、取得时刻 | 前一日收盘信号、下一 UTC 日开盘 |
| 数据 | 原件 URL/批次、SHA、质量、范围 | manifest 与严格字段准入 |
| 规则 | 参数、基线、成本、现金、调仓 | hold vs trend、15 bps、现金零收益 |
| 评价 | 收益、回撤、成本、失效条件 | 同窗口比较，不只挑最高收益 |
| 选择 | 试过多少版本、为什么保留 | 记录失败，不只保存赢家 |
| 交付 | 图表、代码、解释、限制 | Notebook 输出加研究报告 |

小研究用现有文档或 Notebook 记录，不另造通用实验平台。新试验固定输入与规则后再运行；看完结果才改阈值，必须记为新试验。

## 第一阶段：来源地图与质量

阅读 Notebook 00、07 和源码研究报告。验收是能解释每个字段的单位、业务键、时间、覆盖及限制；列出缺失和异常，不以文件存在或行数相同代替完整性。

具体作业：选择 AlgoSeek 中一个 OHLC 越界日期，保留证券 ID 和所有原字段，核对报价时段定义。没有解释前不把它用于成交模拟。选择一条 FRED 月度序列，说明为什么月份标签不是可见时间。

## 第二阶段：AI 基建现金流

阅读 Notebook 03、08。先独立重算 Amazon/Meta 两个 FCF 桥接，核对原文；再解释 Microsoft 财政年与其他公司的差异。

下一批实际工作：在四家公司有限季度范围内建立事实表，逐季核验累计现金流差分和修订身份；将公司总量、分部数据、AI 专项披露分列。验收是每个数字回链到支持它的报表或段落，缺资料时明确拒答。当前 SEC 接口及季度证据是依赖，不能拿年度插值补齐季度。

## 第三阶段：宏观和链上

阅读 Notebook 04、05。先解释三项余额的单位与同日对齐，再比较变化。链上先查最后有效日，再画图；用同链趋势，不跨链硬比较地址数。

验收是能区分存量、流量、价格与实际使用，能说明哪个变量可能修订。正式预测需要额外的发布时间和历史版本；当前只完成描述性研究。

## 第四阶段：基线与验证

阅读 Notebook 01、02、06。保留原 runner，先复现相同数据与参数。明确基础成本，再做预先约定的成本情景；必须包含失败年份和现金基准。训练/验证切分同时考虑标签跨度，不随机打乱时间。

ETF 新回放先导入原输入，校验摘要及公司行动证据。BTC 新试验不能重新命名已看过的样本为留出期。试验记录不足时不计算伪精确的选择偏差校正结果。

## 后续数据与实现优先级

| 优先级 | 交付 | 真实依赖 | 验收 |
| --- | --- | --- | --- |
| P1 | 四公司季度现金流与收入 | SEC 合规身份、可用响应、原文 | 单位/财政期/修订/原文均可查 |
| P1 | 原 ETF/ETH 回放 | 原环境 inputs 与证明文件 | 摘要一致、公司行动及日历通过 |
| P2 | 最新链上有效值 | 社区更新或明确的新来源 | 来源分版、定义对照、有效日核验 |
| P2 | AI 管理层表述档案 | 少量官方电话会/财报文本 | 引文支持结论，表格完整 |
| P3 | 财报检索增强 | 可靠文本、固定测试问题 | 检索、计算、引用、拒答分别通过 |
| P4 | 模型与完整回测 | 无泄漏输入、选择记录、未见期 | 净成本稳定性与失败分析 |
| 暂缓 | 高频、全量公司面板、实盘 | 大容量、权限、实时和恢复要求 | 用户另行安排 |

未完成项不是暗中排队下载的任务。本次没有启动后台采集、交易或自动更新。大数据由用户后续决定；新增小数据仍必须遵守 300 MB 硬上限。

## 如何维护这份教材

改公共逻辑后运行定向测试和 `python -m tools.research_playbook.render`，检查表格单位、图例和输出；不是只检查 Python 无语法错误。准备器改变会导致 manifest 摘要变化，执行回执应同步更新。原件不可静默覆写，生产来源继续由原 Java 链路管理。

Notebook 是教学入口，公共函数只抽取确有多个消费者的规则。不要复制整个 ML4Trading 框架，也不要把财务业务规则塞进 `utils`。报告数值更新必须引用新数据版本，说明比较窗口是否改变。
